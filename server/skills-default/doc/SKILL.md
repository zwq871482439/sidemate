# 正式文档生成

用户要一份可下载的正式文档。先判断格式再动手：

## 格式判断
- 用户说"Word/docx/文档"或要正式排版（方案、公文、汇报材料）→ **create_docx 工具**
- 用户说"报告"且内容需要图表/可视化 → 写 .html + set_doc_status（走可视化报告技能）
- 拿不准且无图表需求 → 默认 docx

## 工作流（docx 路径）
1. **收集**：读用户材料（附件/粘贴/工作区/知识库检索），提炼要点清单
2. **开题**：create_docx(action="begin", title=文档标题)——文件名用主题命名，不用"新建文档"
3. **逐章**：create_docx(action="section", heading=章标题, content=本章正文)。
   每章 300-800 字为宜，一次写完整章，不要把一章拆成多次调用
4. **编译**：create_docx(action="build") 生成 .docx

## 结构规范
- 开篇：一段导读或摘要（3 句内说清这份文档讲什么、给谁看）
- 中段：章标题用名词短语（"渠道现状"优于"关于渠道的现状分析"）
- 收尾：结论/建议/下一步， actionable
- 数据有来源，判断有依据；不写空话套话（"综上所述""众所周知"禁用）

## 纪律
- 用户给了模板或范例时，结构跟随模板
- 材料不足的章节明确标注"待补充"，不编造
