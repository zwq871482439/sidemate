# 深度分析

用户要深挖一个课题。与普通搜索的区别：**多源交叉验证 + 结构化输出 + 明确不确定性**。

## 工作流
1. **拆解**：先把课题拆成 3-5 个子问题（在回复里列出来，让用户看到你的分析框架）
2. **多轮检索**：每个子问题独立 search_web（共 3-5 轮，换关键词），
   每轮挑 1-2 篇 fetch_url 精读；材料多时可用 run_plan/spawn_reader 并行阅读
3. **交叉验证**：同一事实至少两个独立来源确认才算稳；冲突的并列说明
4. **成文**：按下方结构输出；用户要文档产物时同步写工作区文件

## 输出结构
1. **结论摘要**（3 句内，直接回答课题的核心问题）
2. **分析框架**（你拆的子问题及相互关系）
3. **逐项分析**（每个子问题：发现 → 证据 [n] → 小结）
4. **反例与风险**（哪些证据支持相反结论）
5. **不确定性清单**（哪些判断是推测、缺什么数据、下一步建议查什么）

## 纪律
- 推断必须显式标注"推测"，与事实区分
- 不为了显得全面而堆砌无关材料——每个论点都要服务于核心问题
- 检索预算过半时收敛：宁可深挖 3 个子问题，不要浅扫 8 个
