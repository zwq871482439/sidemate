## 三、模式系统重构（2026-06-18 新增）

### 3.1 背景

当前模式系统混乱：
- **Chat Tab**：本地 / 云端 两档切换
- **文库 Tab**：独立对话窗口，带"云端对比"隐藏开关
- **痛点**：用户要在两个 Tab 之间切换才能用"本地安全+云端补充"的对比模式；文库 Tab 职责不清（既管上传又管对话）

### 3.2 目标架构（⚠️ 三模式并存，非替代关系）

> 🚨 关键澄清（2026-06-19 21:13 用户决策）：
> - 三种模式**长期并存**，互不替代
> - 在线模式**永久保留**，令牌系统是它的隐私层（P5 做）
> - 隐私混合模式是**新增的独立模式**，不是在线模式的升级版
> - 用户按场景选：纯本地 / 信任云端 / 想要云端但怕泄露

```
┌─ 模式选择（Chat Tab 顶部下拉）──────┐
│  🏠 本地模式                          │  纯本地 LLM，完全不上云（P4 已有）
│  ☁️ 在线模式                          │  纯云端 + 令牌系统（P4 已有 + P5 强化）
│  🛡️ 隐私混合模式（名字待定）          │  本地代理 + 脱敏草稿（P6 新增）
└─────────────────────────────────────┘
```

**Chat Tab 主体按模式自动切换后端 pipeline**：

| 模式 | 后端 pipeline | 隐私机制 | KB 访问 | 上线版本 |
|------|--------------|---------|---------|---------|
| 🏠 本地模式 | `local_pipeline` | 完全不上云 | 本地 LLM 自由访问 | P4 |
| ☁️ 在线模式 | `cloud_pipeline` | **令牌系统** | 云端受令牌+权限控制 | P4+P5 |
| 🛡️ 隐私混合 | `hybrid_pipeline`（新）| **脱敏草稿** | 云端只看草稿不看原文 | **P6 新增** |

### 3.3 知识库 Tab 改造（原"文库 Tab"）

**⚠️ 名字变更**：文库 → **知识库**（更准确，反映"档案管理"定位）

**改造前**：文库 Tab = 档案管理 + 对话（混在一起，职责不清）
**改造后**：知识库 Tab = **纯档案管理**

知识库 Tab 职责：
- 文档上传/删除/批量操作
- 自动打标 + 人工修正
- Tag 聚类展示
- 检索测试 playground
- 🔒 隐私标记（私密文档）
- 知识自动关联（P6+ 扩展，待定）

**对话功能迁出**：
- 原文库 Tab 的本地问答 → 迁到 Chat Tab 的"🛡️ 隐私混合模式"
- 原文库 Tab 的云端对比 → 同上（隐私混合模式替代）
- 知识库 Tab **不再有任何对话功能**

### 3.4 用户心智模型简化

**改造前**（用户困惑）：
- "我要查文库应该去哪个 Tab？" → 文库 Tab
- "我要对比本地和云端应该去哪？" → 也去文库 Tab，但要打开隐藏开关
- "本地模式怎么用文库？" → Chat Tab 本地模式会自动检索

**改造后**（清晰统一）：
- 所有对话都在 Chat Tab（按模式分流）
- 想要什么效果选对应模式即可
- 知识库 Tab 只管"我有哪些文档"（纯档案管理）

### 3.5 隐私混合模式（核心创新 - 名字待定）

> 💡 命名候选：隐私混合 / 混合增强 / 本地代理 / 双引擎 / 守门人
> 用户原话："这名字还得改"

**核心痛点**（用户深度思考后定调）：
> 本质上是不想让大模型看到我本地知识库里有什么东西。
> 宝贵文档喂给大模型 = 免费训练材料 + 丢失风险 + 泄露风险。

**旧对比模式的本质缺陷**：
- 本地和云端**都看 KB**（隐私问题）
- 令牌系统只是"渐进暴露"，云端调一次 search_kb 内容还是出去了

**隐私混合模式架构**（本地代理 + 脱敏草稿）：

```
用户问题："中医怎么调理脾胃"
   ↓
[本地 LLM 做智能路由 + 脱敏代理]
   ├─ 公开知识问题 ─────────────────→ 云端回答（不碰 KB）
   │  例："什么是脾胃"
   │
   ├─ 私有知识问题 ──→ 本地 LLM 检索 KB → 本地生成答案（不上传）
   │  例："我的养生笔记里怎么说的"
   │
   └─ 混合问题 ──→ 本地 LLM 用 KB 生成"脱敏草稿" → 云端润色
      例："根据我的笔记 + 通用知识，分析脾胃调理"
       (云端只看草稿，不看原始 chunk)
```

**关键创新：脱敏草稿（Sanitized Draft）**

```
原始 chunk: "张三的体检报告显示肝功能异常 ALT 86"
   ↓ 本地 LLM 脱敏
脱敏草稿: "体检报告显示某指标偏高，需要调理肝脏"
   ↓ 发给云端
云端润色: "肝功能指标偏高建议从饮食、作息、中药三方面调理..."
   ↓ 本地合成
最终答案: 云端润色 + 本地从 KB 提取的个性化建议
```

**对比新旧方案**：

| 维度 | 旧对比模式 | 新隐私混合 |
|------|-----------|-----------|
| 本地 LLM 看 KB | ✅ | ✅ |
| 云端看 KB 原文 | ❌（隐私问题）| ✅ 永远看不到 |
| 云端看脱敏草稿 | — | ✅（可选，用户控制）|
| 云端训练风险 | 高 | 低 |
| 本地 LLM 角色 | 平等贡献者 | **守门人 + 代理** |

### 3.6 隐私混合模式的 UI 动画（愿景，待 UX 细化）

用户期望的"动作可见性"动画（用小人物气泡表达流程）：

```
┌─────────────────────────────────────────────┐
│  👤 用户：中医怎么调理脾胃？                  │
│     [💭 思考气泡]                             │
│                                              │
│  🤖 本地助手：让我查一下...                  │
│     [📚 翻书动画] → 检索 KB                  │
│     [✍️ 写草稿动画] → 生成脱敏草稿           │
│                                              │
│  ☁️ 云端助手：（收到草稿）                   │
│     [💭 思考动画] → 基于草稿 + 通用知识回答  │
│                                              │
│  🤖 本地助手：[✍️ 整合动画]                  │
│     综合 KB 原始信息 + 云端回答              │
│     [💬 最终答案]                            │
└─────────────────────────────────────────────┘
```

**UI 设计原则**：
- **双列布局废弃**（旧对比模式的双列效果一般）
- **单列 + 时间线动画**（小人物 + 气泡表达流程）
- **可见性**：用户能清楚看到"本地在干啥" + "云端在干啥" + "信息从哪来"
- **本地 think 关闭**：4B 模型开 think 出问题，用结构化流程替代

### 3.7 本地 4B 模型的能力边界（关键约束）

**现实**：4B 模型太弱，开 think 会出各种问题。

**应对策略**：
- 不依赖本地 LLM 的"自由思考"
- 用**结构化流程**（Pipeline）强制执行：
  1. 路由分类（公开/私有/混合）→ 简单 prompt
  2. KB 检索 → 工具调用（不需要思考）
  3. 脱敏草稿生成 → 固定模板 + 关键信息提取
  4. 最终合成 → 固定模板 + 信息融合

**复杂回答能力不足时**：
- 答不出的私有问题 → 诚实告知"本地能力有限，建议切到在线模式"
- 混合问题的合成 → 如果本地合成质量差，可以只展示脱敏草稿 + 云端润色（不做深度融合）

### 3.8 实施复杂度评估

| 模块 | 改动 | 复杂度 |
|------|------|--------|
| 模式选择 UI | 加"🛡️ 隐私混合模式"选项 | 低 |
| **hybrid_pipeline**（新） | 路由 → 脱敏草稿 → 云端润色 → 本地合成 | **高** |
| 脱敏草稿生成器 | 本地 LLM + 固定模板，去掉敏感信息 | 中 |
| 文库 Tab 移除对话 | 删除问答区，保留管理区 | 低 |
| Chat Tab 加 KB 问答 action | 新增 `action_mode = 'kb_qa'` | 中 |
| **时间线动画 UI** | 小人物气泡表达流程 | **高**（前端工作量） |
| 设置页迁移 | 文库 Tab 的"云端对比"开关删除 | 低 |
| 用户引导 | 首次进入隐私混合模式的 tooltip | 低 |

**总复杂度**：高。建议 P6 商业化之后单独做一版（P7 模式重构 + 隐私混合）。
