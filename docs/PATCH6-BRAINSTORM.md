## 三、模式系统重构（2026-06-18 新增）

### 3.1 背景

当前模式系统混乱：
- **Chat Tab**：本地 / 云端 两档切换
- **文库 Tab**：独立对话窗口，带"云端对比"隐藏开关
- **痛点**：用户要在两个 Tab 之间切换才能用"本地安全+云端补充"的对比模式；文库 Tab 职责不清（既管上传又管对话）

### 3.2 目标架构

```
┌─ 模式选择（Chat Tab 顶部下拉）──────┐
│  🏠 本地模式                          │  纯本地 LLM，隐私优先
│  ☁️ 在线模式                          │  纯云端，最快最强
│  🔀 对比模式                          │  本地+云端，安全融合
└─────────────────────────────────────┘
```

**Chat Tab 主体按模式自动切换后端 pipeline**：

| 模式 | 后端 pipeline | 行为 |
|------|--------------|------|
| 本地模式 | `local_pipeline` | Qwen3.5-4B 推理，可调 KB 检索作上下文补充 |
| 在线模式 | `cloud_pipeline` | DeepSeek/GPT 直接回答，可调 KB 检索 + search_web |
| 对比模式 | `compare_pipeline` | 本地安全查询（KB 全文不出本机） + 云端补充（只发公开问题） → 本地模型融合两路结果 |

### 3.3 文库 Tab 改造

**改造前**：文库 Tab = 上传管理 + 独立对话（本地 / 云端对比）
**改造后**：文库 Tab = **纯管理**（上传 / 打标 / 检索测试 / 删除）

原文库 Tab 的对话功能分流：
- **本地问答** → Chat Tab 本地模式下的 action 按钮（`action_mode = 'kb_qa'`，类似现有的 'agent'/'chat'）
- **对比模式** → Chat Tab 顶部选"🔀 对比模式"直接进入

### 3.4 用户心智模型简化

**改造前**（用户困惑）：
- "我要查文库应该去哪个 Tab？" → 文库 Tab
- "我要对比本地和云端应该去哪？" → 也去文库 Tab，但要打开隐藏开关
- "本地模式怎么用文库？" → Chat Tab 本地模式会自动检索

**改造后**（清晰统一）：
- 所有对话都在 Chat Tab
- 想要什么效果选对应模式即可
- 文库 Tab 只管"我有哪些文档"

### 3.5 实施复杂度评估

| 模块 | 改动 | 复杂度 |
|------|------|--------|
| 模式选择 UI | 加"对比模式"选项到现有下拉 | 低 |
| Chat Tab pipeline 分流 | `compare_pipeline` 已有（Patch3 写过），接通即可 | 中 |
| 文库 Tab 移除对话 | 删除问答区，保留管理区 | 低 |
| Chat Tab 加 KB 问答 action | 新增 `action_mode = 'kb_qa'`，前端按钮切换 | 中 |
| 设置页迁移 | 文库 Tab 的"云端对比"开关删除 | 低 |
| 用户引导 | 首次进入对比模式的 tooltip | 低 |

**总复杂度**：中等。建议 P6 商业化之后单独做一版（可命名为 P7 模式重构）。

## 四、设置页 Tab 化（2026-06-19 从 P5 推迟）

**说明**：P5 讨论时决定，设置页重构跟模式重构一起做（P6/P7）。

### Tab 结构

```
[常规] [云端 AI] [知识库] [隐私安全] [关于]

常规 Tab：
- 模式选择（本地/云端/对比）← 保留顶部，不在这里
- 系统资源占用（只读展示，不可调）
- 数据目录 + 磁盘占用
- 反馈渠道

云端 AI Tab：
- API 配置（地址/Key/模型）
- Token 预算（本地模式 16K / 云端自动）

知识库 Tab：
- 文档统计（40/200）
- 检索质量（实时检索测试）
- 权限管理（B3）

隐私安全 Tab：
- 数据存储位置
- 隐私声明
- 数据导出/备份

关于 Tab：
- 版本号
- CHANGELOG
- THIRD-PARTY 许可
```

### 跟 P6 模式重构的关系

设置页 Tab 化跟模式系统重构强耦合：
- 模式选择器位置（保留顶部 vs 移到设置）
- 云端 AI Tab 的内容跟模式相关
- 知识库 Tab 的权限管理跟模式相关

**建议**：P6/P7 模式重构时一起做，避免改两次。
