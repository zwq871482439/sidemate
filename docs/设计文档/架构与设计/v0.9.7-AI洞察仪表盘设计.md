## 1. 概览

AI 洞察仪表盘由**后端两轮 LLM + 前端可视化**组成：

| 阶段 | 位置 | 职责 |
|------|------|------|
| **第一轮** | 后端 `api_kb_overview_refresh` | 标签归并（碎片 → 3-5 大类） |
| **第二轮** | 后端 | 叙事型洞察（基于归并后的聚类） |
| **追问生成** | 后端 | 独立 LLM 调用，生成 3 条具体追问 |
| **可视化** | 前端 `_kbRenderInsightDashboard` | 环形图 + 文字 + 追问按钮 |
| **持久化** | 后端 | `data/kb/insight.json`（刷新不丢失） |

整体走**本地 Ollama**（StreamEngine），文档内容**永不离开本机**。

## 2. 后端流程

### 2.1 入口

```python
@router.post("/api/kb/overview/refresh")
async def api_kb_overview_refresh(request: Request):
    """AI 知识库洞察 · 自动整理

    两轮 LLM：
      第一轮 — B3 叙事型洞察（分析文档内容结构，发现隐藏主题）
      第二轮 — 标签归并（碎片标签收敛为宽泛大类）

    返回 insight 文本 + 归并后的 tags + 文档计数。
    """
```

### 2.2 数据收集

```python
doc_list = []
cat_counts = {}
for d in all_docs:
    fname = d.get("filename", "未知")
    cat = (d.get("category") or "").strip()
    tags = d.get("tags") or []
    doc_list.append({
        "title": fname,
        "category": cat,
        "tags": [t for t in tags if t],
    })
    if cat:
        cat_counts[cat] = cat_counts.get(cat, 0) + 1
```

**关键点**：
- `cat_counts` 用 `category` 字段统计
- `doc_list` 收集 title + category + tags

### 2.3 fallback：category 为空时用 doc.tags

```python
# Fix: category 为空时，改用 doc.tags 收集碎片标签作为归并输入
if not cat_counts:
    tag_counts = {}
    for d in doc_list:
        for t in d.get("tags", []):
            if t:

    cats_text = "\n".join(
```

### 2.4 第一轮：标签归并

```python
merge_prompt = (
    "你是一位知识库分类专家。以下文档的标签过于碎片化，需要归并为 3-5 个宽泛的大类。\n\n"
    "当前标签：\n%s\n\n"
    "要求：\n"
    "1. 含义相近的标签必须合并（如「中医养生」「中医流派」「中医病机」→ 「中医药与养生」）\n"
    "2. 归并到 3-5 个大类，最多不超过 10 个，宁少勿多\n"
    "3. 输出纯 JSON 数组，每项格式：{\"new\": \"新标签\", \"from\": [\"旧标签1\", \"旧标签2\"]}\n"
    "4. 不准输出 Markdown，不准加解释文字，只剩 JSON\n\n"
    "归并方案 JSON：" % cats_text
)
raw = await _run_async(merge_prompt, max_tokens=400)
```

**关键设计**：
- 强约束输出格式（纯 JSON，不准 Markdown）
- `max_tokens=400` 限制输出长度
- 异步执行（`asyncio` + `ThreadPoolExecutor`）

#### 2.4.1 JSON 解析容错

```python
try:
    start = raw.index("[")
    end = raw.rindex("]") + 1
    merge_plan = json.loads(raw[start:end])
except (ValueError, json.JSONDecodeError):
    merge_plan = []
```

**容错策略**：
- LLM 可能输出 `["xxx"]` 前后有解释文字
- 用 `index("[").rindex("]")` 截取最外层数组
- 解析失败 → `merge_plan = []`（静默降级）

#### 2.4.2 执行归并

```python
if merge_plan:
    for plan in merge_plan:
        new_cat = plan.get("new", "").strip()
        old_tags = plan.get("from", [])
        if not new_cat or not old_tags:
            continue
        old_set = {t.strip() for t in old_tags}
        changed = 0
        for doc in kb.documents.values():
            old_cat = (doc.category or "").strip()
            if old_cat in old_set:
                doc.category = new_cat
                changed += 1
        if changed > 0:
            merges_applied.append({
                "from": list(old_set),
                "to": new_cat,
                "count": changed,
            })

# 持久化
try:
    kb._save_meta()
except Exception:
    pass
```

**关键点**：
- `old_tags` 转为 `set`（去重 + O(1) 查找）
- 每个文档的 `category` 字段直接修改（`doc.category = new_cat`）
- 归并完成后 `kb._save_meta()` 持久化到 `data/kb/kb_meta.json`

### 2.5 第二轮：叙事型洞察

```python
insight_prompt = (
    "你是一位知识库分析助手。根据以下文档聚类，帮用户理解这个文库的实用价值（100-150字）。\n\n"
    "聚类分布：%s\n\n"
    "代表性文档：\n%s\n\n"
    "请直接描述（不要编号，不要套话）：\n"
    "- 这个文库能回答什么问题，适合做哪类讨论\n"
    "- 不同主题之间能怎样交叉产生新想法\n"
    "- 如果要让这个文库更好用，最值得补什么方向\n\n"
    "铁律：\n"
    "- 只输出正文，不要任何标记\n"
    "- 像同事给你介绍资料夹能干嘛，不是写分析报告\n"
    "- 禁止说「您的」「以上」「本文」「综上所述」「缺乏」「不足」「碎片」\n\n"
    "洞察：" % (cluster_summary, cluster_docs_text)
)
insight = await _run_async(insight_prompt, max_tokens=600)
```

**P6 关键改进**：

| 维度 | 旧版 | v0.9.7 |
|------|------|--------|
| **视角** | 学术分析 | 同事介绍 |
| **强调** | 主题覆盖 | 实用价值 |
| **输出** | 罗列分类 | 直接回答问题 |
| **禁词** | 无 | 「您的」「以上」「本文」等套话 |

**质量提升**：
- 「这套资料能干嘛 / 还差啥」而不是「文档 A 涉及 XX 领域」
- 禁词清单防止 LLM 输出「综上所述」类废话

### 2.6 独立生成追问（v0.9.7 关键改进）

```python
suggested_questions = []
try:
    questions_prompt = (
        "你是一位知识库分析助手。基于以下知识库的聚类分布和洞察分析，生成 3 条用户最可能追问的问题。\n"
        "问题必须紧扣文库中的具体文档主题，不能空泛。\n\n"
        "聚类分布：%s\n\n"
        "洞察分析：%s\n\n"
        "要求：\n"
        "1. 输出纯 JSON 数组：[\"问题1\", \"问题2\", \"问题3\"]\n"
        "2. 不准输出 Markdown，不准加解释文字\n"
        "3. 每个问题聚焦具体文档主题的交叉或空白\n\n"
        "追问问题 JSON：" % (cluster_summary, insight[:300])
    )
    q_raw = await _run_async(questions_prompt, max_tokens=200)
    try:
        _start = q_raw.index("[")
        _end = q_raw.rindex("]") + 1
        _parsed = json.loads(q_raw[_start:_end])
        if isinstance(_parsed, list) and all(isinstance(q, str) for q in _parsed):
            suggested_questions = _parsed[:3]
    except (ValueError, json.JSONDecodeError):
        pass
except Exception:
    pass
```

**v0.9.7 改进**：旧版「追问」嵌在 insight prompt 里，LLM 容易给出「请分享更多内容」这类空泛问题。改为**独立 LLM 调用**，追问紧扣文库内容。

**质量提升**：
- 独立 prompt 强调「必须紧扣文库中的具体文档主题」
- 输入包含「聚类分布」+「洞察分析」（`insight[:300]` 截断避免超长）
- 解析 JSON 容错（同上）

### 3.2 数据准备

```js
var catEntries = [];

catEntries.sort(function(a,b){ return b.count - a.count; });
if (catEntries.length > 10) catEntries = catEntries.slice(0, 10);
```

### 3.3 环形图 SVG 生成

```js

donutSvg += '<text x="' + donutCx + '" y="' + (donutCy - 3) + '" text-anchor="middle" class="kb-dash-donut-center" font-size="18">' + totalDocs + '</text>';
```

**视觉结构**：

### 3.4 单分类双弧画圆（v0.9.7 关键修复）

```js
if (sliceAngle >= 2 * Math.PI - 0.001) {
  // 100% 占比时用双弧避免 SVG 退化
  var xm = donutCx + donutR * Math.cos(sa + Math.PI), ym = donutCy + donutR * Math.sin(sa + Math.PI);
  d = 'M' + donutCx + ' ' + donutCy + 
      ' L' + x1.toFixed(1) + ' ' + y1.toFixed(1) + 
      ' A' + donutR + ' ' + donutR + ' 0 1 0 ' + xm.toFixed(1) + ' ' + ym.toFixed(1) + 
      ' A' + donutR + ' ' + donutR + ' 0 1 0 ' + x1.toFixed(1) + ' ' + y1.toFixed(1) + ' Z';
} else {
  var large = (ea - sa) > Math.PI ? 1 : 0;
  d = 'M' + donutCx + ' ' + donutCy + 
      ' L' + x1.toFixed(1) + ' ' + y1.toFixed(1) + 
      ' A' + donutR + ' ' + donutR + ' 0 ' + large + ' 1 ' + x2.toFixed(1) + ' ' + y2.toFixed(1) + ' Z';
}
```

**问题**：当 `sliceAngle = 2π`（单分类全圆），SVG `A` 弧形指令起点和终点重合，**弧形退化为零**，看不到圆。

**修复**：拆成两段 180° 弧拼接：

```
M 50 50  L (50, 6)  A 44 44 0 1 0 (50, 94)  A 44 44 0 1 0 (50, 6)  Z
```

## 4. 自动触发时机

```js

if (typeof kbRefreshOverviewLLM === 'function') {
  setTimeout(function() { kbRefreshOverviewLLM(); }, 300);

// 删除文档后自动触发
setTimeout(function() { if (typeof kbRefreshOverviewLLM === 'function') kbRefreshOverviewLLM(); }, 500);
```

| 触发场景 | 延迟 | 原因 |
|----------|------|------|
| 所有文档打标完成 | 300ms | 让 UI 渲染完文档后再触发 |
| 删除文档 | 500ms | 等后端删除完成 |

## 5. 缓存策略

- **后端持久化**：`data/kb/insight.json`（按 KB 模块隔离）
- **前端不缓存**：每次 `kbRefreshOverviewLLM` 都重新渲染
- **强制刷新**：用户点「整理」按钮强制重新走两轮 LLM

## 6. 失败 / 边界处理

| 场景 | 行为 |
|------|------|
| LLM 未加载 | `_run_async` 抛错 → 回退到模板化洞察 |
| LLM 超时 | StreamEngine 默认 60s → 失败回退 |
| 文档数 = 0 | 返回「知识库为空，请先上传文档」 |
| category 全空 | fallback 到 `doc.tags` 收集 |
| tags 也全空 | fallback 到「文档列表」作为输入 |
| JSON 解析失败 | 静默降级，`merge_plan = []` / `suggested_questions = []` |
| 持久化失败 | 静默跳过（不影响主流程） |
| 目标元素不存在 | 整屏纯遮罩 + 卡片居中 |

## 8. 设计权衡

| 选择 | 理由 |
|------|------|
| **两轮 LLM（先归并后洞察）** | 先归并让聚类更稳定；洞察基于归并结果更聚焦 |
| **独立生成追问** | 嵌在洞察 prompt 里易空泛；独立调用质量更高 |
| **本地 Ollama 推理** | 隐私优先；文档内容不外传 |
| **持久化到 insight.json** | 刷新页面不丢失；减少 LLM 调用次数 |
| **fallback 多级** | LLM 不可用时仍能给出有意义的洞察 |
| **JSON 容错（index + rindex）** | LLM 输出可能含解释文字，截取最外层数组 |
