## 1. 设计背景

### 1.1 重构前的痛点

P6 之前的管道代码中，步骤状态通过散落的变量追踪：

```python
# 旧代码：散落 6 个计时变量
_local_gen_start = time.time()
_cloud_gen_start = time.time()
_local_elapsed = 0
_cloud_elapsed = 0
_merge_start = time.time()
_merge_elapsed = 0
```

问题：
- **变量爆炸**：每个步骤需要 2-3 个变量（开始时间、结束时间、阶段标签）
- **透传困难**：SSE 事件格式不统一，前端解析复杂
- **可维护性差**：新增步骤需要手动管理所有变量

### 1.2 设计目标

用统一的 `Step` 数据类建模流水线的每一步：

```python
@dataclass
class Step:
    id: str             # "local_gen" | "cloud_gen" | "merge" | ...
    label: str          # "本地生成" | "云端补充" | "融合"
    status: str         # "pending" | "running" | "done" | "error"
    started_at: float   # 开始时间戳
    elapsed_ms: int     # 总耗时（毫秒）
    phase: str          # 当前子阶段
    payload: dict       # 额外数据
```

---

## 2. 组件结构

### Step 数据类

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | str | 唯一标识，如 `"local_gen"` |
| `label` | str | 中文标签，如 `"本地生成"` |
| `status` | str | `pending` / `running` / `done` / `error` |
| `started_at` | float | 开始时间 (`time.time()`) |
| `elapsed_ms` | int | 耗时（毫秒），完成后计算 |
| `phase` | str | 子阶段标签 |
| `payload` | dict | 额外透传数据 |

### SSE 事件格式

```json
{
    "type": "step",
    "channel": "local",
    "step": {
        "id": "local_gen",
        "label": "本地生成",
        "status": "running",
        "phase": "started"
    }
}
```

## 3. 管道中的应用

### 3.1 local_pipeline

```python
step_local = Step("local_gen", "本地生成")
yield step_to_sse(step_local, "start")

# ... KB 检索 + 生成 ...

yield step_to_sse(step_local, "done")
step_local.mark_done()
```

### 3.2 parallel_pipeline

```python
step_local  = Step("local_gen", "本地生成")
step_cloud  = Step("cloud_gen", "云端补充")
step_merge  = Step("merge", "融合")

# 并行执行，每个 Step 独立计时
# drain 合并时通过 Step 对象避免丢事件
```

### 3.3 前端渲染

CardRenderer 接收 `step` 类型事件，渲染为阶段卡片：

```
┌─ 本地生成 ────── 3.2s ─┐
│ ✓ 已完成                  │
└──────────────────────────┘
┌─ 云端补充 ────── 自动跳过 ─┐
│ ○ 未启用云端                 │
└──────────────────────────┘
┌─ 融合 ────── 1.1s ─┐
│ → 正在合并...         │
└──────────────────────┘
```
