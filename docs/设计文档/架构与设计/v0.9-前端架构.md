## 1. 概述

### 1.1 技术选型

桌伴前端采用**传统 `<script>` 标签引入**模式（非 ES Module / 非 SPA），所有 JS 文件共享全局作用域（`window`）。选择此方案的原因：

- **离线部署友好**：无需构建工具、打包器，直接由 FastAPI 静态目录 serve
- **依赖关系简单**：通过脚本加载顺序控制依赖，无 npm/yarn
- **目标用户群体**：桌面应用内嵌浏览器（Go Launcher 打开 `localhost`）

### 2.2 Tab 系统

四个 Tab 通过 `switchTab(name, btn)` 切换，使用 CSS class `active` 控制显隐：

| Tab | DOM ID | 说明 |
|-----|--------|------|
| 对话 | `#tab-chat` | 默认活跃，消息列表 + 输入框 |
| 文库 | `#tab-qa` | 需安装 knowledge 扩展才显示 |
| 纪要 | `#tab-minutes` | 需安装 recorder 扩展才显示 |
| 设置 | `#tab-settings` | 始终显示 |

Tab 恢复机制：切换时将当前 Tab 名存入 `localStorage._activeTab`，页面刷新后由底部 IIFE 恢复。

Tab 动态显隐：`updateTabVisibility()` 根据 `/api/extensions/list` 返回的扩展类型，控制文库/纪要 Tab 的 `display`。

### 2.3 模态框 / Overlay

| 组件 | 用途 |
|------|------|
| `#chatModelOverlay` | 模型未预热遮罩（首次引导 / 锁屏） |
| `#kbModelOverlay` | 文库Tab模型未预热遮罩 |
| `#kbLockOverlay` | KB处理中锁定对话区 |
| `#modeConfirmModal` | 模式切换确认弹窗 |

| `#moduleLoadingOverlay` | 模块加载全局覆层 |
| `#loadingOverlay` | 启动连接遮罩 |

### 3.2 模块加载顺序

```html
<!-- 第三方库 -->
<script src="purify.min.js">
<!-- 核心模块 -->
<script src="api.js">        <!-- ① fetch封装 -->
<script src="utils.js">      <!-- ② 工具函数 -->
<script src="errors.js">     <!-- ③ Toast/心跳 -->
<script src="stream_renderer.js"> <!-- ④ 流式渲染器 -->
<!-- 功能模块 -->
<script src="settings.js">   <!-- ⑤ 设置Tab -->
<script src="qa.js">         <!-- ⑥ 文库Tab -->
<script src="minutes.js">    <!-- ⑦ 纪要Tab -->
<!-- chat子模块 -->
<script src="chat-session.js">  <!-- ⑧ 会话管理 -->
<script src="chat-actions.js">  <!-- ⑨ Action管理 -->
<script src="chat-files.js">    <!-- ⑩ 文件操作 -->
<script src="chat-export.js">   <!-- ⑪ 导出 -->
<script src="chat-ui.js">       <!-- ⑫ UI辅助 -->
<script src="chat.js">          <!-- ⑬ 对话核心（最后加载） -->
```

**关键原则**：`chat.js` 必须最后加载，因为它依赖所有子模块的函数定义。

### 3.3 各模块职责

#### api.js
- **职责**：`fetchWithTimeout()` 超时封装（默认10s），`apiUrl()` 路径辅助
- **暴露函数**：`fetchWithTimeout`, `apiUrl`
- **无依赖**

#### utils.js
- **职责**：`iconSvg()` 离线SVG图标库（17种图标）、`md()` Markdown渲染、`esc()` HTML转义、`formatStats()` 统计行格式化
- **核心函数**：
  - `iconSvg(name, size)` — 替代emoji的SVG图标系统，`stroke="currentColor"` 继承父色
  - `md(text, sanitize)` — Markdown→HTML，集成 marked.js + KaTeX + highlight.js + DOMPurify
  - `_extractAndRenderLatex(text)` — LaTeX公式提取与占位符保护
  - `_renderFootnotesFallback(html, rawText)` — 脚注后处理兜底

#### errors.js
- **职责**：Toast通知中心（队列+去重+防重入）、离线降级UI、心跳检测（30s）、自定义弹窗`showDialog()`
- **核心机制**：

  - Toast 队列：同时最多3个，超出排队
  - Toast 防重入：相同 key 的 toast 只保留一个

#### stream_renderer.js
- **职责**：Chat/KB 共用的流式渲染节流器
- **全局常量**：`STREAM_RENDER_INTERVAL = 100`（毫秒）
- **API**：

  ```javascript
  renderer.flush();    // 强制立即渲染
  renderer.finalize(); // 流结束时调用
  ```
- **暴露**：`StreamRenderer`, `STREAM_RENDER_INTERVAL`

## 4. SSE 流式渲染

### 4.1 双管道架构

```
用户提问
  ├── Chat管道（/api/chat/stream）
  │   ├── 本地模式 → local_pipeline.py
  │   └── 云端模式 → cloud_pipeline.py
  └── KB管道
      ├── 本地KB（/api/kb/ask） → qa.js 内消费
      └── 对比模式（/api/chat/stream + kb_compare） → qa.js 双列消费
```

### 4.2 StreamRenderer 共享渲染器

`stream_renderer.js` 提供节流渲染机制，Chat 和 KB 两边共用：

```javascript
// 全局常量，两边统一
var STREAM_RENDER_INTERVAL = 100; // ms

// Chat端使用（chat.js）
var RENDER_INTERVAL = STREAM_RENDER_INTERVAL;
// 手动节流：now - lastRender > RENDER_INTERVAL 时才渲染

// KB端使用（qa.js）
var kbRenderer = new StreamRenderer(aiDiv, {
  renderFn: function(el) {
    el.innerHTML = md(fullAnswer, false) + sourcesHtml;
  }
});
fullAnswer += evt.content;
kbRenderer.tick();
```

### 4.3 Chat 管道 SSE 消费

`sendMessage()` 内部使用 `ReadableStream` 读取器消费 SSE：

1. `fetch('/api/chat/stream')` → 获取 `ReadableStream`
2. `reader.read()` 循环读取 chunk
3. `buffer.split('\n')` 分割 SSE 行
4. 解析 `data: {type, content, ...}` JSON
5. 按 type 分发到对应的渲染逻辑
6. 节流控制：`now - lastRender > RENDER_INTERVAL` 时才更新DOM

### 4.4 KB 管道 SSE 消费

`kbAsk()` 消费 `/api/kb/ask`：

1. 创建 `StreamRenderer` 实例
2. SSE 事件：`status` → `think` → `fold` → `token` → `sources` → `done`
3. `sources` 到达时立即 flush（不节流）
4. 最终 `finalize()` 清除光标

### 4.5 KB 对比模式 SSE 消费

`_kbAskCompareMode()` 消费 `/api/chat/stream`，使用 `channel` 字段分发：

```
channel=local  → 本地列（#kbCompareLocal）
channel=cloud  → 云端列（#kbCompareCloud）
channel=merge  → 融合列（#kbCompareMerge）
channel=progress → 步骤状态更新
```

每列独立实时流式，token 级拼接 + markdown 渲染 + 闪烁光标。

### 5.2 暗色/亮色切换

```javascript
// 初始化（index.html 内联）
(function initTheme() {
  var saved = localStorage.getItem('theme');
  var prefersDark = window.matchMedia('(prefers-color-scheme: dark)').matches;
  if (saved === 'dark' || (!saved && prefersDark)) {
    document.documentElement.setAttribute('data-theme', 'dark');
  }
})();

// 切换函数
function toggleDarkMode(enabled) {
  if (enabled) {
    document.documentElement.setAttribute('data-theme', 'dark');
    localStorage.setItem('theme', 'dark');
    hljsTheme.href = '/static/vendor/highlight-dark.min.css';
  } else {
    document.documentElement.removeAttribute('data-theme');
    localStorage.setItem('theme', 'light');
    hljsTheme.href = '/static/vendor/highlight.min.css';
  }
}
```

## 6. 状态管理

### 6.1 全局变量管理模式

传统 `<script>` 模式下，所有状态通过全局变量管理，无框架响应式系统：

- **会话状态**：`currentMessages[]`, `currentChatFile`, `generating`
- **模式状态**：`window._currentMode`（'local'|'cloud'）, `window._cloudConfigured`
- **KB状态**：`_kbSessionId`, `_kbBusyProcessing`, `_kbGenerating`, `_kbCompareEnabled`
- **纪要状态**：`_recMediaRecorder`, `_recSessionId`, `_recAudioCtx`
- **UI状态**：`_lastScrollBottom`, `_cloudThinking`, `_agentTimelineEl`

### 6.2 会话状态

**Chat 会话**：
- 存储在后端 `data/chats/*.json` 文件
- 前端通过 `currentMessages[]` 数组缓存
- 增量追加渲染优化：已有 `N` 条消息时，只 append 新消息节点

**KB 会话**：
- 独立于 Chat，有自己的 `_kbSessionId`
- 历史通过 `/api/kb/session/context` 管理
- 磁盘持久化：`data/kbsession/{session_id}/round_NNN.json`

### 6.3 模式切换状态

三种 AI 模式通过 `settings.js` 的 `initModeTag()` / `updateModeTagUI()` 管理：

| 模式 | 全局变量 | 说明 |
|------|----------|------|
| local | `window._currentMode = 'local'` | 本地 Ollama 推理 |
| cloud | `window._currentMode = 'cloud'` | 云端 API 推理 |

切换流程：
1. `selectMode(mode)` → 显示确认弹窗
2. `confirmModeSwitch()` → POST `/api/mode/switch`
3. `updateModeTagUI()` → 更新 Tag 文案/颜色/dropdown
4. `refreshStatus()` → 刷新全局状态（模型标签、overlay、资源面板）

## 8. 关键交互流程

### 8.1 发送消息完整流程

```
用户点击发送/Enter
  → sendMessage()
    → 验证（非空、非生成中、模型已加载）
    → 构建 userMsg 对象，push 到 currentMessages
    → generating = true，锁住 session poll
    → renderMessages() 渲染用户消息
    → 文件上传（如有 pendingFile）
    → KB引用捕获（_savedRefPath）
    → 清理UI（按钮、输入框、文件指示器）
    → appendStreamingMsg('思考中...')
    → 创建 AbortController
    → Token粗估 + 自动裁剪历史
    → 用户消息落盘（POST /api/chats/{name}/append）
    → POST /api/chat/stream（SSE请求）
      → ReadableStream 循环读取
        → 解析 SSE 行
        → 按 type 分发渲染
          token → fullText += content, 节流渲染
          think_start → 云端思考开始
          think_token → _cloudThinkText 累积
          think_end → 折叠思考
          fold → 本地思考折叠
          done → 最终渲染 + 统计
          error → 错误卡片
          agent_* → Agent时间线
          ... → 其他30+种事件
      → while(true) 循环直到 done
    → finally:
      → 移除 stream-msg id
      → 消息持久化
      → generating = false
      → renderMessages() 全量渲染
      → 恢复UI按钮
      → 刷新会话列表 + 上下文圆环
```

### 8.2 KB 文档上传与检索流程

```
拖拽/点击上传
  → kbOnDrop()/kbOnFilePicked()
    → kbUploadFile(file)
      → POST /api/kb/upload (FormData)
      → kbRefreshDocs()
        → GET /api/kb/documents
        → GET /api/kb/stats
        → 渲染文档列表（状态图标、进度条、标签、摘要）
        → 自动轮询（处理中 → 3s间隔）
```

```
用户提问
  → kbAsk()
    → 验证模型已加载
    → 对比模式检查
    → kbAddMsg('user', text) 渲染用户消息
    → 创建 StreamRenderer
    → POST /api/kb/ask (SSE)
      → status → 思考指示
      → think → 实时思考内容
      → fold → 折叠思考
      → token → fullAnswer 累积，renderer.tick()
      → sources → 来源卡片渲染
      → error → 错误显示
    → finalize()
    → 完成后刷新上下文圆环
```

### 8.3 模式切换流程

```
用户点击 modeTag
  → toggleModeDropdown() 显示下拉
  → selectMode('cloud')
    → 检查 _cloudConfigured
    → 未配置 → showDialog 提示前往设置
    → 已配置 → 显示确认弹窗（模型信息、数据策略）
  → confirmModeSwitch()
    → POST /api/mode/switch
    → updateModeTagUI() 更新Tag
    → refreshStatus() 全局刷新
    → initKbCompareToggle() 同步KB对比开关
```

### 8.4 对比模式双列渲染流程

```
用户开启 KB 对比开关
  → toggleKbCompare(true)
    → 首次弹出隐私说明
    → POST /api/cloud/config 保存状态

用户提问（对比模式）
  → kbAsk()
    → 检测 _kbCompareEnabled
    → _kbAskCompareMode(question)
      → kbAskCompare(question) 生成双列UI
        #kbCompareLocalSteps (本地3步骤)
        #kbCompareLocal (本地列)
        #kbCompareCloudSteps (云端3步骤)
        #kbCompareCloud (云端列)
        #kbMergeSection (融合列，初始隐藏)
      → POST /api/chat/stream (kb_compare=true)
        → channel=local
          step → 更新本地步骤列表
          stream → token 追加到 #kbCompareLocal
          sources → 来源标签
          phase=done → 最终渲染
        → channel=cloud
          status → 更新云端步骤
          stream → token 追加到 #kbCompareCloud
          phase=done → 最终渲染
        → channel=merge
          stream → token 追加到 #kbCompareMerge
          phase=done → 最终渲染
        → done → 刷新上下文圆环
```
