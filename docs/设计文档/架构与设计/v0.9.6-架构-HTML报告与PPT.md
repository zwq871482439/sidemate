## 1. 整体架构

```
用户请求 → AI 写 .html / .ppt.html 源码到 workspace
        ↓
用户调 set_doc_status(filename, "completed")
        ↓
agent_loop.py set_doc_status handler
        ↓
doc_action.py:
  ├── generate_html_report()   # .html  → 内联 marked + mermaid
  ├── generate_ppt_html()      # .ppt.html → 内联 reveal.js + mermaid
  └── generate_docx()          # .md → pandoc
        ↓
写到 workspace/<output>
        ↓
前端渲染 doc_ready → 显示「下载 HTML 报告 xxx.html」按钮
```

**关键设计**：所有产物是**自包含 HTML 单文件**——内置 marked.js / mermaid.js / reveal.js（内联），用户拿 `.html` 文件双击即用，无需联网，无需 Sidemate 运行。

## 2. HTML 报告架构

### 2.1 生成端（Python）

`server/pipelines/doc_action.py::generate_html_report()`

```python
def generate_html_report(content, output_path, title):
    # 1. 处理 mermaid 围栏 → 占位符 + 源码数组
    _mermaid_codes = []
    content = re.sub(r"```mermaid\s*\n(.*?)```", _fence_to_frame, content)

    # 2. marked 在前端处理 Markdown
    _md_input = _json.dumps(content)
    processed_content = '<script type="application/json" id="md-src">' + _md_input + '</script>'

    # 3. 组装 HTML
    html = doctype + style + body + tipbar + processed_content + scripts

    # 4. 写入文件
    write(output_path)
```

### 2.2 浏览器端（前端）

```
HTML 文件结构:
<!DOCTYPE html>
<html>
<head>
  <style>...700 行 CSS...</style>
</head>
<body>
  <div class="report-tipbar">...</div>
  <script type="application/json" id="md-src">"...content..."</script>
  <script>...tryRender: marked.parse(JSON.parse(...))...</script>
  <script>(function(){marked.js})()</script>
  <script>(function(){mermaid.js})()</script>
  <script>var _MERMAID_CODES = [...]; initReportMermaid();</script>
</body>
</html>
```

**核心流程**：

1. 页面加载 → `<script type="application/json">` 提供 LLM 内容
2. tryRender IIFE：等 marked 加载完 → `JSON.parse(s.textContent)` → `marked.parse(txt)` → 替换占位符
3. mermaid 加载完 → 遍历 `.chart-slot` → `mermaid.render(id, code)` → 注入 SVG
4. enhanceMermaidStage：挂滚轮/拖拽/工具栏

### 2.3 关键技术点

| 难点 | 解决方案 |
|------|----------|
| marked v15 UMD 在浏览器挂 `globalThis.marked={parse:fn,...}` 对象（非函数） | 检测 `typeof m.parse === "function"` 而非 `typeof === "function"` |
| HTML attribute 传 JSON 会把 `\n` 解成真换行 | 改用 `<script type="application/json">` |
| `</script>` 字面字符串会提前终止 script | `_json.dumps(...).replace("</", "<\\/")` 转义 |
| mermaid 节点标签里半角双引号破坏语法 | 失败时显示带源码的错误框（**不自动修复**，让 LLM 自己意识到写错） |

Reveal.initialize({
  hash: true,

## 4. 关键技术：单文件自包含

### 4.1 为什么自包含？

- 用户可以**离线打开**报告 / PPT
- **可分享**——单文件邮件附件
- **长期归档**——10 年后还能看（库版本内嵌）

### 4.2 怎么做到？

所有 JS / CSS 用 `open(p, 'r').read()` 读全文，作为 `<script>` 标签插入：

```python
html += '\n<script>(function(){' + marked_js + '\n...})();</script>\n'
```

### 4.3 文件大小

| 文件 | 大小 | 来源 |
|------|------|------|
| marked.min.js | 39 KB | npm marked v15 |
| mermaid.min.js | 3.3 MB | npm mermaid |
| reveal.min.js | 112 KB | npm reveal.js |
| reveal.css | 54 KB | npm reveal.js |
| reveal-theme-white.css | 7 KB | npm reveal.js |
| reveal-theme-black.css | 7 KB | npm reveal.js |
| reveal-reset.css | 1 KB | npm reveal.js |
| HTML 报告 CSS | ~25 KB | 自研 |

**压缩后**（gzip）一个 HTML 报告约 800KB-1MB，PPT 约 1.2MB。

## 5. 渲染失败兜底

### 5.1 mermaid 失败

```js
mermaid.render(id, code).then(res => { slot.innerHTML = res.svg; })
.catch(e => {
  slot.innerHTML = `<div style="...">
    <b>图表渲染失败</b>: ${e.message.slice(0, 200)}
    <details>
      <summary>查看源码</summary>
      <pre>${code}</pre>
    </details>
  </div>`;
});
```

**设计哲学**：**不自动修正**——自动替换双引号会掩盖 LLM 的语法错误，让 LLM 不知道自己写错。

### 5.2 marked 失败

```js
m.parse(txt)  // 如果抛错
.catch(e => console.error("[report] marked parse failed:", e));
// 此时 md-src 已被替换为解析前的字符串
// 用户看到 raw markdown + 解析失败错误
```
