## 1. 配置系统概览

Sidemate 的配置系统采用 **默认值 + 用户覆盖** 的两层结构：

1. **`DEFAULTS` 字典**（`config.py` 中硬编码）— 所有配置项的默认值和唯一真相源
2. **`settings.json`**（运行时持久化）— 用户自定义的配置覆盖

### 加载流程

```
启动 → load_config()
     → 读取 DEFAULTS 字典
     → 合并 settings.json 中的用户值
     → 写入内存缓存 _config_cache
     → 后续通过 config.get() 零磁盘 IO 读取
```

### 关键特性

- **内存缓存**：启动时加载到 `_config_cache`，所有读取操作通过 `config.get(key)` 走内存缓存，零磁盘 IO
- **线程安全**：使用 `_cache_lock` (threading.Lock) 保护缓存读写
- **合并写入**：`save_config()` 采用合并策略，保留已有 key 不覆盖
- **扩展性**：settings.json 可以包含非 DEFAULTS 的 key（如 `scene_skills`），通过 `get()` 一样可读

## 4. settings.json 文件结构

`settings.json` 位于 `server/` 根目录下，是运行时持久化配置文件。

### 读写规则

- **读取**：启动时由 `load_config()` 读取，与 `DEFAULTS` 合并
- **写入**：通过 `save_config()` 合并写入（保留已有 key 不覆盖）
- **缓存**：写入后自动调用 `_invalidate_cache()` 重新加载到内存

### 字段分类

#### 运行时可配置字段

所有 `DEFAULTS` 中的字段都可以出现在 `settings.json` 中。常见运行时配置：

```json
{
  "ai_mode": "local",
  "cloud_base_url": "https://api.openai.com/v1",
  "cloud_api_key": "base64编码的API Key",
  "cloud_model": "gpt-4o-mini",
  "cloud_context_policy": "full",
  "cloud_slim_history_rounds": 6,
  "cloud_context_window": 0,
  "sandbox_cleanup": "24h",
  "default_mode": "qa",
  "memory_budget_mb": 8000,
  "ollama_host": "127.0.0.1",
  "ollama_port": 11434,
  "ollama_model": "qwen3-5-4b",
  "kb_permission": "full",
  "kb_compare_enabled": false,
  "kb_compare_privacy_read": false
}
```

#### 非默认键（扩展字段）

`settings.json` 还可以包含不在 `DEFAULTS` 中的自定义键，同样通过 `config.get()` 读取：

- `scene_skills`：场景技能配置（已归档）
- 其他扩展插件的自定义配置

### 典型 settings.json 示例

```json
{
  "ai_mode": "cloud",
  "cloud_base_url": "https://api.openai.com/v1",
  "cloud_api_key": "c2stdGVzdC1rZXk=",

  "cloud_context_policy": "slim_history",

  "sandbox_cleanup": "7d",
  "memory_budget_mb": 8192,
  "kb_permission": "search-only",
  "kb_compare_enabled": true,
  "kb_compare_privacy_read": true
}
```

## 5. 配置 API

### `config.get(key, default=None)`

从内存缓存读取配置项。零磁盘 IO，线程安全。

```python
from config import get
mode = get("ai_mode")  # 返回 "local" 或 "cloud"
```

### `config.set_value(key, value)`

设置单个配置项并持久化到 `settings.json`。

```python
from config import set_value
set_value("ai_mode", "cloud")
```

### `config.save_config(config_dict)`

批量保存配置。采用合并策略：已有 key 保留原值，新 key 补充写入。

```python
from config import save_config
save_config({"ai_mode": "cloud", "cloud_model": "gpt-4o"})
```

### `config.load_config()`

从磁盘重新加载配置（合并 DEFAULTS + settings.json）。通常只在启动时和缓存失效时调用。

## 6. 运行时目录结构

`config.py` 定义了以下运行时目录常量：

| 常量 | 路径 | 说明 |
|------|------|------|
| `ROOT_DIR` | `server/` | 工作区根目录（`config.py` 所在目录） |
| `DATA_DIR` | `server/data/` | 数据根目录 |
| `CHAT_DIR` | `server/data/chats/` | 对话文件目录 |
| `LOG_DIR` | `server/data/logs/` | 日志目录 |
| `UPLOAD_DIR` | `server/data/tmp_upload/` | 临时上传目录 |
| `FILES_DIR` | `server/data/files/` | 持久化文件目录 |
| `KBSESSION_DIR` | `server/data/kbsession/` | KB 会话目录 |
| `WORKSPACE_DIR` | `server/` | 工作区目录（向后兼容别名） |

所有目录通过 `ensure_dirs()` 在启动时自动创建。

### 配置文件路径

- **配置文件**：`server/settings.json`（`_CONFIG_FILE` 常量）
