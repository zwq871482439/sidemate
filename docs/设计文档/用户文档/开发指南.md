> 版本：v0.9.7 | 面向开发者
>
> 本文档介绍如何参与 Sidemate 的开发、调试和测试。

---

## 1. 环境搭建

### 1.1 前置条件

- Windows 10/11 64-bit
- Python 3.14（项目自带嵌入式 Python，位于 `python/`）
- Go 1.21+（仅修改 Launcher 时需要）
- Git

### 1.2 启动开发环境

```bash
# 克隆仓库
git clone <repo> Sidemate
cd Sidemate

# 方式一：通过 Go Launcher 启动（完整运行时）
.\Sidemate.exe

# 方式二：直接启动 Python 后端（调试用）
./python/python.exe server/server.py
```

`Sidemate.exe` 是 Go Launcher，负责：启动 Python FastAPI 后端 → 后端拉起 llama-server（llama.cpp）→ 加载模型 → Launcher 轮询 `/api/status` 等待就绪 → 打开浏览器。

后端端口：`127.0.0.1:8976`（Python FastAPI）
推理端口：`127.0.0.1:11434`（llama-server）

## 3. SSE 调试

### 3.1 关键规则

**每个 SSE 错误出口必须发 `done` 事件**，否则前端 UI 锁死。

```python
# 正确示例
try:
    yield sse_data(...)
except Exception:
    yield sse_done_event()  # ← 必须！
```

### 3.2 调试 SSE

```bash
# 直接 curl 查看原始 SSE 流
curl -N -X POST http://127.0.0.1:8976/api/chat/stream \
  -H "Content-Type: application/json" \
  -d '{"message":"你好"}'
```

### 3.3 常见问题

| 问题 | 原因 | 解决 |
|------|------|------|
| 前端 UI 卡死 | SSE 缺少 done 事件 | 检查所有 `except` 出口 |
| 流式断掉 | 超过 60s 超时 | 调整 `timeout` 参数 |
| 离线模式无反应 | 模型未加载 | 检查 `/api/status` |
| 看门狗不重启 | 重启次数达上限（3次/小时）| 等 1 小时或手动重启 |

## 5. 测试

### 5.1 运行测试

```bash
# 回归测试（需要 Node.js）
node tests/test_regression_v097.mjs   # v0.9.7 回归（84 项）
node tests/test_regression_d8fad96.mjs # 旧版回归（25 项）
node tests/_self_test.mjs             # 自测（10 项）
```

### 5.2 测试说明

| 文件 | 说明 |
|------|------|
| `test_regression_v097.mjs` | v0.9.7 主回归套件（模型下载/KB洞察/三模式等） |
| `test_regression_d8fad96.mjs` | 历史回归（mermaid/PPT/KB等） |
| `_self_test.mjs` | 基础功能自测（Markdown/代码块/LLM类） |

### 5.3 注意事项

- 部分测试项需要 server 在运行（在线测试），否则跳过
- 测试用 Node.js ESM 格式（`.mjs`），不依赖额外包
- 改功能后必须跑全部 3 套测试确认不破坏

---

## 6. 铁律

- 改 `server/*.py` 后重启 `Sidemate.exe`（或 Python 进程）即生效
- 改前端 JS 后更新 `index.html` 的 `?v=` 版本号防缓存
- SSE 每个错误出口必须发 `done` 事件
- 别删 `workspace/` 目录（用户文档产物）
- 别碰 `python/` `models/` `lib/`（运行时资源，不进 git）
- 改已有功能后必须跑回归测试
- 看门狗重启上限 3 次/小时，测试时频繁杀进程会触发限流
