# AI 洞察仪表盘使用指南

> ✅ **本文档随 0.9.6 首发重发**（功能已在 0.9.6 完整发版）。
>
> 版本：v0.9.7 | 文件：`server/static/js/qa.js`（`kbRefreshOverviewLLM` / `_kbRenderInsightDashboard` / `_kbRenderCategoryTree`）
> 适用人群：知识库管理员 / 想快速了解 KB 整体内容价值的用户

---

## 1. 概览

AI 洞察仪表盘是 KB Tab 顶部的核心模块。它由**本地 LLM**（qwen3.5-4b）驱动，对你的整个知识库做一次深度分析，输出三大产出：

1. **环形图** —— 文档分类占比可视化
2. **洞察文字** —— 主题覆盖、交叉价值、补充方向分析
3. **建议追问** —— 3 条紧扣文库的追问按钮，点击直接跳转 Chat 提问

整个过程在**本机完成**，文档内容不上传任何云端。

## 3. 整理按钮（kbRefreshOverviewLLM）

### 3.1 触发方式

- **手动触发**：点击工具栏右侧「**整理**」按钮（带循环图标）
- **自动触发**：
  - 所有文档处理完毕（含 AI 打标）后 300ms 自动触发一次
  - 删除文档后 500ms 自动触发一次

### 3.2 触发时的 UI 变化

| 元素 | 整理前 | 整理中 |
|------|--------|--------|
| 「整理」按钮 | 「整理」 | 「整理中...」（带 spin 图标，disabled） |
| 侧栏标题 | 「AI 智能筛选」 | 「AI 智能筛选 — 重新整理中...」 |
| 仪表盘内容 | 上次生成的洞察 | 「AI 正在分析文档结构，生成洞察中...」 |

整理完成后：

- 按钮恢复「整理」可点击
- 仪表盘刷新为新生成的洞察
- 侧栏标签树自动重渲染（分类可能已变更）
- 文档列表自动刷新（统计信息同步）

### 3.3 失败处理

如果 LLM 调用失败（超时 / 模型未加载 / 网络问题）：

- Toast 提示「AI 整理失败，请重试」
- 仪表盘内容恢复为整理前的状态
- 按钮恢复可点击，可手动重试

## 4. 环形图（Donut Chart）

### 4.1 视觉规格

- **尺寸**：100px SVG（在仪表盘主体左侧）
- **配色**：10 色调色板 `_DONUT_COLORS`：

```js
['#7F77DD', '#4F8CC9', '#3DA89E', '#6BA845', '#DA9A2E',
 '#D95468', '#8B5CF6', '#3B82C4', '#5C8A5A', '#C97D60']
```

每个分类按文档数占比从大到小排，配色循环分配。

### 4.2 渲染规则

- **多分类**：每段弧长 = `count / total * 2π`
- **单分类**：100% 占比下，SVG 单弧会退化。用**双弧画全圆**（两段 180° 弧拼接），保证视觉闭合
- **空 KB**：不渲染环形图，显示「点击整理触发 AI 洞察」

### 4.3 联动行为

环形图扇区、图例、侧栏色点**三重联动**：

| 触发点 | 行为 |
|--------|------|
| 点击扇区 | 该分类文档排序置顶，扇区加 `.donut-active` 描边 |
| 点击图例项 | 同上 |
| 点击侧栏色点 | 同上 |

再次点击或点击其他分类 → 切换焦点；点击空白处 → 取消筛选。

## 5. 洞察文字

### 5.1 生成流程

`kbRefreshOverviewLLM()` 内部走两轮 LLM 调用：

1. **第一轮（合并）**：本地 LLM 接收所有 doc.tags → 归并为 3-5 个宽泛大类（避免碎片化）
2. **第二轮（独立追问生成）**：独立 LLM 调用生成 3 条追问（不嵌在洞察 prompt 中，避免空泛）

> P6 修复：旧版「追问」嵌在洞察 prompt 里时，LLM 容易给出「请分享更多内容」这类空泛问题。v0.9.7 改为独立调用，追问紧扣文库内容。

### 5.2 fallback 机制

如果第一轮 merge 收到的 `category` 字段为空（极端情况），前端 fallback 到 `doc.tags` 收集，确保不喂空数据导致 LLM 瞎编。

### 5.3 洞察文字结构

| 段落 | 内容 |
|------|------|
| **主题** | 整个文库的核心主题（一句话概括） |
| **覆盖** | 涵盖的子领域（2-4 个） |
| **价值** | 这套资料的实际用途 / 适合谁用 |
| **补充** | 还可以补哪些方向（2-3 个建议） |

> **P6 改进**：洞察 prompt 从「学术分析」改为「价值导向」—— 不再罗列「文档 A 涉及 XX 领域」这类废话，而是直接告诉用户「这套资料能干嘛 / 还差啥」。

### 5.4 来源标识

仪表盘下方显示「**本地 AI 整理**」字样 + 更新时间，强化「数据不出本机」的可信度。

## 6. 追问按钮

### 6.1 形态

仪表盘底部 3 个 pill 按钮，每个按钮是一句话问题，紧扣文库内容。

### 6.2 点击行为

- 跳转 Chat Tab
- 把问题自动填入输入框
- 不自动发送（用户可修改后再发）
- 切 Tab 时保留输入框内容（即使已切到其他 Tab）

### 6.3 典型例子

假设 KB 是「中医药与养生」：

> - 追问 1：「基于这些资料，能不能给我一个调理肠胃的方案？」
> - 追问 2：「中医和现代营养学在抗氧化方面有哪些共识？」
> - 追问 3：「适合老年人的养生茶饮有哪些推荐？」

这些追问会引用 KB 文档回答（Chat 在线模式 + KB 权限 = full / search-only 时）。

## 7. 侧栏标签树（_kbRenderCategoryTree）

### 7.1 渲染规则

- 按 AI 归并后的 category 分组
- 每个分类一项：色点（与环形图同色）+ 分类名 + 文档数
- 文档数最多的分类排最前
- 颜色与环形图 / 图例一一对应（共用 `_DONUT_COLORS`）

### 7.2 智能筛选占位

**未生成 category 的文档**统一归入「**正在等待智能筛选**」分组：

- 视觉：虚线空心圆点（`.kb-tag-pending`），区别于已分类的实心色点
- 计数：显示未分类文档数
- 行为：点击进入「正在等待智能筛选」视图
- 消失：整理完成后自动消失（文档已分配到对应分类）

### 7.3 筛选行为

- 点击某分类 → 只显示该分类文档（`kbFilterByTag`）
- 再次点击或点其他分类 → 切换
- 再次点击同一分类 → 取消筛选
- 整合到环形图 / 图例联动中

## 8. 文档卡片（kbRenderDocs）

### 8.1 卡片内容

每张卡片显示：

- **文件名**（截断省略号）
- **AI 标签**（3-5 个 tag pill）
- **摘要**（1-2 行）
- **元数据**：文件大小 / 词元数 / 被搜索次数 / 上传时间
- **热力图指示器**：彩色圆点（灰/琥珀/红）显示被搜索热度
- **操作按钮**：查看 / 删除 / 私密 / 重新生成标签

### 8.2 视图切换

工具栏右侧可切换：

- **卡片视图**（默认）：自适应网格
- **列表视图**：紧凑列表

切换时保留筛选条件。

### 8.3 排序

- 默认按上传时间倒序
- 筛选某分类时：分类文档置顶
- 重新触发整理后：自动按新分类排序

## 9. 完整使用流程

### 9.1 首次使用

1. 打开 KB Tab
2. 上传第一份文档
3. 等待打标完成（后台 P2 任务，不阻塞 UI）
4. 仪表盘自动触发「整理」（所有文档处理完才触发）
5. 看到环形图 + 洞察文字 + 追问按钮
6. 点击追问跳到 Chat 提问

### 9.2 持续运营

1. **新增文档**：上传后 AI 自动打标，分类归入对应类别
2. **删除文档**：500ms 后自动触发整理，仪表盘 / 侧栏 / 卡片同步更新
3. **重新生成标签**：单文档卡片 → 「重新生成标签」按钮（`kbRetrySummary`）
4. **重新整理**：手动点「整理」按钮，强制重新归并 + 生成洞察

### 9.3 文档较多时

- KB 最多支持 200 个文档（`kb_max_documents: 200`）
- 整理一次约 3-10 秒（取决于文档数和 LLM 速度）
- 仪表盘刷新期间可继续浏览文档

## 10. 常见问题

### Q1：仪表盘一直显示「正在分析知识库...」？
可能 LLM 尚未加载或调用超时。检查：
- 设置 → 常规 → 模型管理，确认 LLM 状态为「loaded」
- 浏览器 F12 → Network 查看 `/api/kb/overview-llm` 状态
- 重试：点「整理」按钮

### Q2：环形图只显示一段（不是闭合的圆）？
这是已修复的 v0.9.5 旧 bug。v0.9.7 单分类时用双弧画全圆。如果你看到不闭合的圆，说明浏览器缓存了旧版 JS，按 `Ctrl+Shift+R` 硬刷新。

### Q3：侧栏分类很多很碎？
点「整理」按钮，AI 会自动归并为 3-5 个宽泛大类。如果归并不满意，删除部分低质量文档后再整理。

### Q4：追问按钮点击没反应？
检查：当前是否在 KB Tab？追问按钮会切到 Chat Tab 并填入输入框，但**不会自动发送**。如没切换 Tab，可能是 welcome-tour 的引导遮罩没关闭，按 Esc 退出引导。

### Q5：「正在等待智能筛选」一直不消失？
- 整理按钮被点击过吗？没点过的话，AI 不会主动归并
- 如果点过后还有 → 检查是否有文档打标失败（卡片上「重新生成标签」按钮可见）

### Q6：洞察文字说「这套资料很碎片」？
可能 KB 文档数太少（< 3 篇）或者主题不集中。AI 洞察受文库质量影响，上传更多相关文档可改善。

### Q7：能导出洞察吗？
当前版本：仪表盘内容为前端渲染，无法直接导出。可手动复制文字。v0.9.8 计划加「导出洞察报告」按钮。

## 12. 设计理念

- **可读性优先**：洞察文字避免学术腔，**面向用户价值**而非面向分析者
- **零数据外传**：所有 LLM 调用走本地 Ollama，云端无法参与
- **透明可见**：每步操作（整理 / 删除 / 重标）都有 UI 反馈
- **智能筛选兜底**：未归类的文档不会"消失"，有占位分组
