# 知识库权限与令牌（AccessToken）说明

> ✅ **本文档随 0.9.6 首发重发**（功能已在 0.9.6 完整发版）。
>
> 版本：v0.9.6 | 文件：`server/core/access_token.py` / `server/static/js/kb-batch.js`
> 适用人群：关心文档隐私 / 需要细粒度授权 / 想理解云端可见性的用户

---

## 1. 为什么需要权限与令牌

桌伴 Sidemate 的核心承诺是「数据不出本机」，但用户在以下场景下需要更精细的控制：

- **本地 + 云端混合**：希望本地 AI 可见所有文档，但**只对部分文档授权云端**
- **分享**：把 KB 中某篇文档分享给同事 / 朋友，对方在云端模式下也能引用
- **临时授权**：用一次性令牌给某次外部会话访问权，过期自动失效

为解决这些场景，桌伴提供了**两层机制**：

1. **文档级私密标记（`is_private`）**：决定云端 AI 是否默认可见
2. **三级令牌系统（AccessToken）**：按文档粒度灵活授权 `full` / `search` / `none`

---

## 2. 文档级私密标记

### 2.1 概念

每个 KB 文档有一个布尔字段 `is_private`（持久化在 `data/kb/kb_meta.json`）：

| `is_private` | 含义 | 默认可见性 |
|--------------|------|------------|
| `false` | 公开文档 | 本地 + 云端均可见 |
| `true` | 私密文档 | 本地可见；**云端默认不可见** |

### 2.2 设为私密

#### 单文档操作

打开 KB Tab → 找到目标文档卡片 → 点击「私密」图标（锁标）→ 确认。

#### 批量操作

1. 勾选多个文档
2. 顶部出现批量工具栏
3. 点击「设为私密」按钮
4. 弹窗文案：**「设为私密后，云端模型将无法读取该文档内容。」**
5. 确认后私密标记写入 `kb_meta.json`

#### 取消私密

流程同上，按钮文案变为「取消私密」，弹窗提示：
> **「取消私密后，文档将恢复对云端模型可见，所有已有令牌将被撤销。」**

注意：取消私密会**主动撤销该文档所有未过期令牌**（fail-safe，避免遗留令牌被滥用）。

### 2.3 私密文档的云端行为

| 场景 | 私密文档 | 公开文档 |
|------|----------|----------|
| 离线模式检索 | ✅ 可见 | ✅ 可见 |
| 在线模式 + 无 API Key | ❌ 在线模式无法启用 | ❌ 在线模式无法启用 |
| 在线模式 + KB 权限 = full | ❌ 默认屏蔽 | ✅ 可见 |
| 在线模式 + KB 权限 = search-only | ❌ 默认屏蔽 | ✅ 可见 |
| 并行模式 | ❌ 默认屏蔽 | ✅ 可见 |
| 本地 AI 直接读全文 | ✅ 不受限制 | ✅ 可见 |

**关键点**：本地 AI 对**所有文档**（无论是否私密）都有完整读取权。私密只针对**云端**生效。

## 3. KB 权限配置（kb_permission）

### 3.1 三档配置

设置 → 知识库 → 「云端 AI 访问本地知识库」开关有 3 档（`server/config.py`）：

| 配置值 | 含义 | 适用场景 |
|--------|------|----------|
| `full` | 公开文档**全文**注入云端 prompt | 默认值；适合信任云端、追求最佳答案 |
| `search-only` | 仅向云端发送检索关键词，不发送文档内容 | 适合敏感场景：希望云端辅助但不暴露数据 |
| `disabled` | 云端模式完全不访问 KB | 适合纯本地优先用户 |

### 3.2 切换入口

**设置 Tab → 知识库 → 滚动到「云端 AI 访问本地知识库」**。

切换时弹窗提示风险（搜索 only 档会显著降低云端回答质量）。

### 3.3 与三模式联动

| 模式 | `full` | `search-only` | `disabled` |
|------|--------|---------------|------------|
| **离线** | 不涉及 | 不涉及 | 不涉及 |
| **在线** | KB 全文注入 | KB 关键词注入 | 无 KB 上下文 |
| **并行** | 本地检索 + 云端**摘要**补充 | 本地检索 + 云端关键词补充 | 本地检索 + 云端无 KB 上下文 |

> **并行模式特殊说明**：KB 原文**永不离开本机**。即便 `full` 档，云端看到的也只是本地生成的摘要（memory_local），不会拿到文档 chunk 原文。

## 4. 三级令牌系统（AccessToken）

### 4.1 令牌级别

`server/core/access_token.py` 定义了三档令牌：

| 级别 | 含义 | 场景 |
|------|------|------|
| **`full`** | 全文可见 | 分享给完全信任的人，对方在云端模式下可读全文 |
| **`search`** | 检索可见 | 允许对方云端检索到该文档，但不暴露文档级摘要 |
| **`none`** | 不可见 | 等同于无令牌；主要用于「撤销」语义 |

### 4.2 令牌数据结构

```python
@dataclass
class AccessToken:
    token: str          # 32 字节随机 hex（64 字符）
    doc_id: str         # 绑定的文档 ID
    level: str          # "full" | "search" | "none"
    session_id: str     # 关联会话 ID（""=未关联）
    created_at: float   # 创建时间戳
    expires_at: float   # 过期时间（0=永不过期）
```

### 4.3 令牌生命周期

- **生成**：调用 `generate_full_token(doc_id)` / `generate_search_token(doc_id)`
- **验证**：`verify_token(token, doc_id)` → `(is_valid, level)`
- **过期**：默认 `expires_at=0`（永不过期），可通过 `access_token_default_ttl` 配置
- **撤销**：
  - 单个撤销：`revoke_token(token)`
  - 文档级撤销：`revoke_doc_tokens(doc_id)`（取消私密时自动调用）
  - 会话级撤销：`revoke_all_for_session(session_id)`
  - 全量撤销：进程重启（令牌**仅存内存，不持久化**）

### 4.4 私密文档过滤逻辑

`filter_private_docs()` 是核心过滤函数：

```python
def filter_private_docs(self, doc_ids, token, is_private_map):
    is_valid, level = self.verify_token(token)
    bound_doc_id = None
    if is_valid and level == "full":
        # full 令牌只对绑定的 doc_id 放行，其他私密仍屏蔽
        with self._lock:
            _tok = self._tokens_cache.get(token)
            bound_doc_id = _tok.doc_id if _tok else None

    accessible = []
    for doc_id in doc_ids:
        is_private = is_private_map.get(doc_id, False)
        if not is_private:
            accessible.append(doc_id)  # 公开：始终放行
        else:
            # 私密：只有 full 令牌 + 绑定的 doc_id 才放行
            if is_valid and level == "full" and bound_doc_id == doc_id:
                accessible.append(doc_id)
    return accessible
```

**关键设计**：

- **公开文档不受令牌影响**（任何人都能看）
- **私密文档必须 full 令牌 + 绑定的 doc_id 同时成立才放行**（最小授权原则）
- **search 令牌不能放行任何私密**（只能在公开文档检索时被验证，但**不能用于读私密**）

### 4.5 性能与安全

- **线程安全**：所有读写操作加 `self._lock`（`threading.Lock`），避免并发冲突
- **LRU 淘汰**：每个 doc_id 最多保留 1000 个令牌，超限淘汰最旧
- **过期清理**：`verify_token` 时若发现过期，自动从缓存清理
- **fail-safe**：令牌失效 / 撤销时，私密文档一律不放行（绝不默认放行）

## 5. 用户操作流程

### 5.1 创建令牌（前端）

> 当前版本：v0.9.6 令牌的创建 / 撤销主要通过内部 API 调用。UI 入口计划在 v0.9.8 完善。

**临时方案**（开发测试用）：

```js
// 在 KB 文档卡片上点击「令牌」按钮（实验性）
// 弹出对话框选择 full / search + 有效期
// 生成的令牌字符串通过弹窗显示 + 复制按钮
```

### 5.2 使用令牌

如果你是被分享方：

1. 收到令牌字符串（64 字符 hex）
2. 在 KB 检索时附带令牌（API 调用层）
3. 系统自动验证令牌 → 决定哪些私密文档可访问

### 5.3 撤销令牌

1. 文档作者打开 KB 卡片
2. 点击「管理令牌」按钮
3. 选择「全部撤销」或「按 ID 撤销」
4. 后端调用 `revoke_doc_tokens(doc_id)`

## 6. 配置项速查

`server/config.py` 相关配置：

| 键 | 默认 | 说明 |
|----|------|------|
| `kb_permission` | `"full"` | 云端 AI 访问 KB 范围 |
| `access_token_default_ttl` | `0` | 令牌默认有效期（秒），0=永不过期 |
| `kb_search_top_k_local` | `3` | 本地模式检索 top-k |
| `kb_search_top_k_cloud` | `5` | 云端模式检索 top-k |
| `kb_context_max_chars_local` | `5000` | 本地模式注入 KB 总字符上限 |
| `kb_context_max_chars_cloud` | `12000` | 云端模式注入 KB 总字符上限 |

## 7. 常见问题

### Q1：设为私密后，本地 AI 也读不到？
**不会**。本地 AI 对所有文档有完整读取权。`is_private` 只对**云端**生效。

### Q2：令牌会不会过期？
默认永不过期（`access_token_default_ttl=0`）。如果设置非 0 值，则到期后自动失效。

### Q3：进程重启后令牌还在吗？
**不在**。令牌仅存内存，不持久化。重启后需要重新生成。这是有意设计（P5 决策）—— 防止长期遗留令牌被滥用。

### Q4：能否撤销单个令牌？
可以。`revoke_token(token_str)`。前端 UI 入口 v0.9.8 完善。

### Q5：在线模式下，私密文档在检索结果中会显示吗？
**不会**。`filter_private_docs()` 在检索前就过滤掉。云端模型根本不知道这些文档存在。

### Q6：并行模式怎么平衡 KB 可用性和隐私？
并行模式云端只看到本地生成的**摘要**（memory_local），看不到 chunk 原文。摘要不包含敏感内容（由本地 LLM 提炼）。所以并行模式 `kb_permission=full` 时**仍然安全**。

### Q7：我设置了 `kb_permission=search-only`，云端 AI 怎么工作？
云端会收到 KB 检索的**关键词**（来自 bge-m3 embedding 余弦 top-k），但**不会**收到 chunk 文本。云端仅基于这些关键词 + 自身知识回答。

## 8. 隐私边界总结

```
┌─────────────────────────────────────────────┐
│  本地 AI                                      │
│  ├── 公开文档：可见 ✅                        │
│  └── 私密文档：可见 ✅（不受 is_private 限制） │
└─────────────────────────────────────────────┘
                  ↓ 离线模式 / 知识库内回答
              （始终在本地）

┌─────────────────────────────────────────────┐
│  云端 AI（在线 / 并行模式）                   │
│  ├── 公开文档：可见（取决于 kb_permission）   │
│  └── 私密文档：默认不可见                     │
│        + full 令牌绑定 → 可见（仅 chunk）     │
│        + search 令牌 → 仍不可见              │
│        + 无令牌 → 不可见                     │
└─────────────────────────────────────────────┘
```

**Sidemate 的承诺**：除非你**显式授权**（设公开 + kb_permission=full）或**主动分享令牌**，你的文档内容**永远不会被云端 AI 看到**。
