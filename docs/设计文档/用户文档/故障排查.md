# 故障排查指南

> 版本：v0.9.7（当前发版）
>
> v0.9.7 底座为 **llama.cpp（llama-server.exe，端口 11434）**，Python 后端 FastAPI（端口 8976），由 **Go launcher（Sidemate.exe）** 统一管理，看门狗负责崩溃自动重启。

---

## 1. llama-server 问题

### 现象：启动报「端口 11434 被占用」

**原因**：llama-server 默认端口被其他程序（或其他本地 AI 工具）占用。

**排查**：
```bash
# 查看占用进程
netstat -ano | findstr :11434
```

**解决**：
1. 根据上面命令返回的 PID，在任务管理器结束对应进程
2. 或重启电脑释放端口
3. 8976 端口（Python 后端）同理排查：`netstat -ano | findstr :8976`

### 现象：模型加载失败 / llama-server 反复重启

**排查**：
1. 确认已在「设置 → 模型下载」下载完整模型，下载页显示「已加载」
2. 确认模型文件未损坏——可删后在下载页重新下载
3. 检查内存是否充足：
   - 0.8B 需 ~1.5GB，2B 需 ~3GB，4B 需 ~6GB
   - 内存不足会加载失败，降一档模型重试
4. 查看 `data/logs/` 中 llama-server 日志，寻找 `failed to load model` / `out of memory`

**解决**：
- 内存不够 → 换更小档位（4B → 2B → 0.8B）
- 关闭其他大内存程序后重启 Sidemate

### 现象：GPU / Vulkan 不生效，跑在 CPU 上很慢

**排查**：
1. 确认显卡支持 Vulkan（多数近 5 年的独显支持）
2. 更新显卡驱动到最新
3. 在「设置 → 常规」确认推理后端选了 Vulkan / GPU
4. 查看日志是否有 `vulkan: device not found` 或 `fallback to CPU`

**解决**：
- 驱动更新后重启
- 老旧集显可能不支持 Vulkan，此时只能用 CPU（建议用 0.8B 或 2B 档位）

## 2. 知识库（KB）问题

### 现象：上传文档一直「排队中」/ 提示嵌入模型未就绪

**原因**：KB 模型（bge-m3 + bge-reranker-v2-m3，共 ~4.5GB）未加载。

**排查**：
1. 「设置 → 模型下载」确认 KB 模型组合已下载且状态为「已加载」
2. 检查 `/api/kb/module-status`，确认 embedding 与 reranker 都 ready
3. 查看日志是否有模型加载错误

**解决**：
- 未下载 → 下载 KB 模型组合
- 已下载未加载 → 重启 Sidemate
- 卡死 → 重启后存量文档会自动恢复处理

### 现象：检索不准 / 答非所问

**排查**：
1. 确认 reranker（bge-reranker-v2-m3）已加载——它对检索精度影响很大
2. 文档数过多（接近 200 上限）会稀释精度，清理无关文档
3. 检查问题是否过于模糊，改用含文档关键词的具体提问
4. 尝试切换 KB 问答引擎为 cloud（设置 → 知识库 → kb_ai_mode），用云端模型回答

### 现象：报错「向量维度不匹配」

**原因**：知识库索引是用旧版 embedding 模型生成的，与当前 bge-m3 维度（1024）不一致。常见于从旧版本升级且 KB 有存量数据。

**解决**：
1. 清空知识库索引（文库 Tab → 管理 → 清空，或删除 `data/kb/` 下的向量索引文件）
2. 重新上传文档，用当前 bge-m3 重新向量化
3. 重启 Sidemate

## 3. 界面问题

### 现象：页面白屏 / 内容不显示

**解决**：
1. F5 刷新；持续白屏则 Ctrl+Shift+R 硬刷新
2. 重启 Sidemate
3. 推荐用 Chrome 或 Edge 浏览器
4. 检查 Python 后端（8976）是否在运行：`curl http://127.0.0.1:8976/api/health`

### 现象：流式回答中断，发送按钮灰色卡死

**原因**：SSE 流式连接的某个错误出口未正常发送 `done` 事件。

**排查**：
1. F12 → Network → 找到 `/api/chat/stream` 请求
2. 看 EventStream tab 是否有 `done` 事件
3. 检查 `data/logs/` 是否有 llama-server 崩溃或超时记录

**解决**：
- 新建对话重试
- 若 llama-server 崩溃，看门狗会自动重启（3 次/小时上限）；超上限需手动重启 Sidemate

### 现象：暗色模式部分元素颜色异常

切换到亮色再切回，或硬刷新（Ctrl+Shift+R）。

## 4. 看门狗 / 进程问题

### 现象：llama-server 或 Python 后端频繁崩溃重启

**机制说明**：Go launcher 的看门狗监控 llama-server 与 Python 后端，崩溃后自动重启，上限 **3 次/小时**。超限后停止自动重启，需手动处理。

**排查**：
1. 查看 `data/logs/` 日志，定位崩溃原因（常见：内存不足、模型损坏、端口冲突）
2. 若是内存不足 → 降模型档位
3. 若是模型损坏 → 重新下载模型
4. 若是端口冲突 → 见 §1 端口占用处理

**解决**：修复根因后重启 Sidemate，看门狗恢复正常工作。

### 现象：托盘图标消失但进程还在

**原因**：launcher 异常退出，但子进程未清理。

**解决**：
1. 任务管理器结束所有 `llama-server.exe`、`python.exe`、`Sidemate.exe` 进程
2. 重新启动 Sidemate

## 5. 报告 / PPT 生成问题

### 现象：HTML 报告 mermaid 图「渲染失败**

LLM 写的 mermaid 语法有错。常见错：
- 节点标签里用了半角双引号 `"..."`（改用中文引号 `「」`）
- 关键字拼写错（如 `florchart` 应为 `flowchart`）

**解决**：hover 错误框看「查看源码」，复制到 https://mermaid.live 验证；让 AI 重新生成或自己改源码。

### 现象：PPT 打开是空白页

F12 看 Console 是否报 `Reveal is not defined`。重新生成 PPT（确认服务端版本 ≥ v0.9.6-final）。

### 现象：PPT 导出 PDF 背景是白色

导出 PDF 时勾选「背景图形」，边距选「无」。

## 6. 通用排查步骤

按顺序尝试，能解决大部分问题：

1. **硬刷新**：`Ctrl + Shift + R`
2. **重启**：托盘右键退出 → 重新启动 Sidemate
3. **查日志**：`data/logs/` 目录（含 llama-server 日志、Python 后端日志、launcher 日志）
4. **健康检查**：
   ```bash
   curl http://127.0.0.1:8976/api/health       # Python 后端
   curl http://127.0.0.1:11434/health          # llama-server
   ```
5. **检查磁盘**：`data/kb/` 所在磁盘剩余 > 2GB
6. **检查内存**：任务管理器看内存占用，过高则关闭其他程序或降模型档位
7. **重置配置**：删除 `settings.json` 后重启（自动恢复默认值）
8. **紧急模式**：「设置 → 常规」切到 CPU 推理后重启
