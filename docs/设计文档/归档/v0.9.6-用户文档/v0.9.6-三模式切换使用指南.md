# 三模式切换使用指南

> ✅ **本文档随 0.9.6 首发重发**（功能已在 0.9.6 完整发版）。
>
> 版本：v0.9.6 | 覆盖 `并行模式使用指南.md`（v0.9.6 旧版已迁入 `归档/`）
> 文件：`server/static/js/chat-actions.js` / `server/pipelines/parallel_pipeline.py`

---

## 1. 概览

Sidemate v0.9.6 起 Chat Tab 顶栏提供**三段式模式按钮组**，取代旧的 tag 下拉。三种模式对应三种 AI 推理策略，覆盖**完全本地 / 完全云端 / 融合**三大场景：

| 模式 | 数据流向 | 适用场景 |
|------|----------|----------|
| **离线** | 100% 本地 | 隐私敏感、纯本地优先、无网络 |
| **在线** | 100% 云端 | 联网需求、追求最强模型、KB 权限可控 |
| **并行** | 本地 KB + 云端融合 | 既有本地知识库又要云端广度 |

---

## 2. 离线模式

### 2.1 特点

- **完全本地推理**：基于 Ollama + Qwen3.5-4B GGUF
- **零网络请求**：对话内容、文档内容均不上传
- **响应速度**：CPU 模式 3-8 字/秒；GPU 模式 10-30 字/秒
- **上下文窗口**：默认 16K（v0.9.7 起支持动态 num_ctx）

### 2.2 支持的功能

| 功能 | 是否支持 |
|------|----------|
| Chat 对话 | ✅ |
| 上传文件作为上下文 | ✅ |
| 引用 KB 文档（查知识库 action） | ✅ |
| 写文档（doc_action） | ✅ |
| 联网搜索 | ❌（无网络） |
| Agent 工具调用 | ❌（受限） |

### 2.3 UI 标识

顶栏「离线」按钮高亮（品牌色 #1E3A5F），对话区上方面板显示「本地 AI · qwen3.5-4b」。

---

## 3. 在线模式

### 3.1 特点

- **云端 API 调用**：OpenAI 兼容协议（GPT-4o / Claude / DeepSeek / Gemini 等 82+ 模型）
- **支持联网搜索**：通过 CloudEngine + SearchEngine（Bing）
- **支持 Agent 工具调用**：`search_web` / `fetch_url` / `summarize_history` / `search_kb`
- **响应速度**：受网络 + 云端服务限制
- **上下文窗口**：取决于所选模型（Claude 200K / GPT-4o 128K / DeepSeek 64K 等）

### 3.2 前置配置

1. **设置 Tab → 云端 AI**
2. 填写：
   - **Base URL**（接口地址）
   - **API Key**（云端服务密钥）
   - **Model**（模型名称）
3. 点击「保存」
4. 自动验证模型是否可用

### 3.3 支持的功能

| 功能 | 是否支持 |
|------|----------|
| Chat 对话 | ✅ |
| 联网搜索 | ✅（默认开） |
| Agent 多轮工具调用 | ✅ |
| 引用 KB 文档 | ✅（取决于 `kb_permission`） |
| 写文档 | ✅ |
| 大上下文长对话 | ✅（受模型限制） |

### 3.4 隐私边界

- **对话内容**发送至云端服务商
- **KB 内容**是否发送取决于 `kb_permission` 配置（见 `v0.9.6-知识库权限与令牌.md`）
- **本地文件**（非 KB 引用）不会自动发送
- **输出过滤**：`response_filter.py` 移除敏感信息残留

### 3.5 UI 标识

顶栏「在线」按钮高亮，对话区上方面板显示「云端 · {模型名}」。

## 4. 并行模式（P6 核心创新）

### 4.1 核心理念

**本地知识库 + 云端通用知识** = 融合回答。两路独立：

- **本地列**：检索 KB → 本地 LLM 基于 KB 内容生成
- **云端列**：基于用户问题 + 通用知识独立生成
- **融合**：本地模型综合两路信息，输出最终回答

### 4.2 数据隔离原则

> **KB 原文永不离开本机**。

云端模型只看到本地生成的摘要（`memory_local`，≤200 字），无法访问文档 chunk 原文。

### 4.3 何时使用

- KB 中有相关资料，**但**本地模型答得不够全
- 需要**云端广度知识**补充本地深度
- 不能把 KB 全文给云端（隐私/合规）
- 想用 KB 的同时**利用最新云端知识**

### 4.4 启用方式

1. Chat Tab 顶栏点击「**并行**」按钮
2. 弹出确认对话框：
   - 说明：「本地检索 KB + 云端通用知识独立回答，本地自动融合」
   - 风险：「对话摘要将发送至云端（KB 原文不外传）」
3. 确认后切换

### 4.5 AgentTimeline 四步时间线

每次提问后，前端 AgentTimeline 展示实时进度：

| 阶段 | 耗时 | 产出 |
|------|------|------|
| **检索** | ~0.5s | KB top-k chunk 列表 |
| **本地生成** | 3-10s | 本地 LLM 基于 KB 的回答 |
| **云端补充** | 3-15s | 云端 LLM 基于通用知识的回答 |
| **融合** | ~1s | 综合两路生成最终回答 |

历史消息持久化可回放（每步耗时 + 产出预览）。

### 4.6 齿轮开关：「允许云端生成关键词」

并行模式下输入框旁有**齿轮开关**（`server/static/js/chat-actions.js`）：

| 状态 | 行为 |
|------|------|
| **关闭**（默认） | 仅用用户原始问题检索 KB |
| **开启** | 云端先拆解 3-5 个检索关键词，本地据这些关键词重新检索 |

**适用场景**：

- 用户问题含糊时，开关开启能提高本地召回率
- 问题明确时，关闭可减少云端调用次数
- 担心云端看到原问题时，关闭（云端只能看到问题，看不到检索词）

对应配置：`config.py` → `parallel_keyword_gen`（半持久化）。

### 4.7 双线记忆

并行模式维护两套独立记忆：

| 字段 | 含义 |
|------|------|
| `memory_local` | 本地列原始回答摘要（≤200字） |
| `memory_cloud` | 云端列原始回答（≤300字） |

切换到「离线」时只读 `memory_local`；切换到「在线」时只读 `memory_cloud`。**互不干扰**。

### 4.8 UI 标识

- 顶栏「并行」按钮高亮
- 进度条上方显示「并行 · 本地 + 云端」
- AgentTimeline 四步进度实时更新
- 最终回答有「融合」标记

## 5. 切换流程

### 5.1 触发切换

点击顶栏三段按钮中的任一非当前模式 → 弹出确认弹窗。

### 5.2 切换确认弹窗

| 字段 | 内容 |
|------|------|
| 标题 | 「切换到 {目标模式}？」 |
| 说明 | 目标模式的功能描述 |
| 风险 | 数据流向 + 隐私边界提醒 |
| 按钮 | 「确认切换」/「取消」 |

### 5.3 切换后行为

- 当前对话消息保留（历史可读）
- 后续消息按新模式生成
- 上下文指示器（Token 条）按新模式容量重置
- 已有 AgentTimeline 状态保留

### 5.4 不允许的切换

- 在线模式 + 未配置 API Key → 弹窗阻止切换
- 并行模式 + 未配置 API Key → 弹窗阻止切换
- 三模式间任意切换可自由进行（不会丢失历史）

| 维度 | 离线 | 在线 | 并行 |
|------|------|------|------|
| **数据流向** | 本地 | 云端 | 本地 KB + 云端 |
| **需要 API Key** | ❌ | ✅ | ✅ |
| **需要联网** | ❌ | ✅ | ✅ |
| **KB 检索** | ✅（手动引用） | ✅（自动或手动） | ✅（自动） |
| **联网搜索** | ❌ | ✅ | ❌（KB 优先） |
| **Agent 工具** | 受限 | ✅ | ✅（云端列） |
| **响应速度** | 中（受本地硬件） | 中（受网络） | 较慢（四步） |
| **知识广度** | 受限于 LLM | 最广 | KB 深度 + 云端广度 |
| **隐私性** | 最高 | 最低 | 中（摘要外发） |
| **上下文窗口** | 16K | 取决于模型 | 取决于模型 |
| **写文档** | ✅ | ✅ | ✅ |
| **典型场景** | 隐私敏感 | 联网强需 | 混合场景 |

## 8. 最佳实践

### 8.1 何时用离线

- 涉及**敏感信息**（财务、医疗、法律）
- **无网络**环境
- **快速问答**（短问题，KB 已有相关资料）

### 8.2 何时用在线

- **联网搜索**需求（新闻、最新数据）
- **复杂推理**（数学、代码、跨领域）
- **大上下文**长对话
- KB 中**没有**相关资料

### 8.3 何时用并行

- KB 中**有**相关资料但不够全
- 需要**结合最新通用知识**
- 不能把 KB 全文给云端
- 想**双保险**（本地列验证云端列准确性）

### 8.4 切换时机

- **对话内切换**：可在消息之间切换，模型独立维护历史
- **新建对话**：建议新主题开新对话，避免上下文混淆
- **模式选择冲突**：先想清楚「这题是隐私优先还是广度优先」

## 9. 常见问题

### Q1：切换模式后之前的对话会丢吗？
**不会**。历史消息保留，下次进入对话时按当前模式读取对应记忆（`memory_local` 或 `memory_cloud`）。

### Q2：并行模式下云端能看到我的 KB 文档吗？
**不能**。云端只能看到本地生成的摘要（`memory_local`，≤200 字）。KB chunk 原文留在本机。

### Q3：在线模式下能引用 KB 文档吗？
**能**，但取决于 `kb_permission` 配置：
- `full`：KB 全文注入云端 prompt
- `search-only`：仅发送检索关键词
- `disabled`：KB 不可访问

### Q4：三种模式哪个回答质量最高？
取决于场景：
- 知识类（KB 内有）：**并行** 最高
- 通用类（KB 外）：**在线** 最高
- 隐私类：**离线** 最高（即便牺牲质量）

### Q5：并行模式回答很慢怎么办？
- 关闭「允许云端生成关键词」开关（节省一轮云端调用）
- 减少 KB 文档数（缩小检索范围）
- 检查本地模型是否在 GPU 模式

### Q6：齿轮开关是全局的吗？
**半持久化**。保存在 `settings.json` 的 `parallel_keyword_gen` 字段，下次启动会保留。

### Q7：能自己写新的模式吗？
当前版本不支持。v1.0 计划开放 Plugin API。

### Q8：模式切换弹窗太烦，能关掉吗？
v0.9.6 不支持关闭。v0.9.8 计划加「设置 → 隐私安全 → 不再显示模式切换确认」开关。
