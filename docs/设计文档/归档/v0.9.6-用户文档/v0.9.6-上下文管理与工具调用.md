# 上下文管理与工具调用

> ✅ **本文档随 0.9.6 首发重发**（agent 循环改进是 0.9.6 重要新功能）。
>
> 版本：v0.9.6 | 适用人群：使用在线 Agent 模式、做长任务、调试工具调用异常的用户

---

## 1. 什么是"上下文管理"

Sidemate 在线 Agent 模式（`Action=agent`）下，AI 会自动判断是否需要调用工具（搜索、读文件、写文档等），多轮交替完成复杂任务。

**核心约束**：

- **总轮次上限**：20 轮（一次性任务）
- **单工具上限**：搜索类工具限制（详见下文）
- **总 token 上限**：~12 万字符（防上下文爆炸）

这些约束的目的是防止 AI 死循环、token 爆炸。

## 2. 工具分类（v0.9.6 起）

### 2.1 Cheap 工具（不计轮次）

本地、不消耗 token 预算的操作，**不计 MAX_ROUNDS**：

| 工具 | 说明 |
|------|------|
| `read_workspace` | 读取工作区文件 |
| `read_workspace_chunk` | 分块读大文件 |
| `list_workspace` | 列出工作区文件 |
| `list_docs` | 列出已完成文档 |
| `summarize_history` | 压缩历史 |
| `get_current_time` | 获取当前时间 |
| `calculator` | 算术 |
| `format_convert` | 文件格式转换 |
| `table_ops` | 表格读写 |

> **效果**：之前 AI 反复读同一文件 19 次就触发 20 轮上限，现在读 30 次也不会卡。

### 2.2 Expensive 工具（计轮次）

调用模型、消耗 token 的操作：

| 工具 | 单次上限 |
|------|----------|
| `search_web`（联网搜索） | 3 次 |
| `search_kb`（KB 检索） | 5 次 |
| `fetch_url`（读网页） | 5 次 |
| `write_workspace`（写文件） | 不限 |
| `set_doc_status`（生成产物） | 不限 |

### 2.3 工具调用流程

```
用户提问 → AI 判断是否需要工具
  ├─ Cheap 工具（如读文件） → 直接执行，不消耗轮次预算
  └─ Expensive 工具（如搜索）
     ├─ 未达上限 → 执行 + 轮次 +1
     └─ 已达上限 → 拒绝并提示"已达上限"
```

## 3. actionBar 一键生成报告

v0.9.6 起，AI 消息下方出现 **actionBar**（操作栏），包含：

- 📄 **生成可视化报告** — 把当前回答转成 HTML 报告
- 🎬 **生成 PPT** — 把当前回答转成演示文稿
- 📋 **复制** — 复制整段回答
- 🔄 **重新生成** — 重新回答

> **省 token 技巧**：直接点 actionBar 的"生成可视化报告"，不用让 AI 在新一轮里再读上下文。

## 4. 工具调用异常处理（v0.9.6 起）

### 4.1 之前的痛点

AI 调用工具失败时，前端只显示「操作异常」4 个字，不知道具体原因。

### 4.2 现在的行为

错误状态会显示**具体原因**：

| 现象 | 含义 | 解决 |
|------|------|------|
| 文件不存在：xxx.docx（文件可能在远程而非工作区） | LLM 用错了远程文件名 | 改用 `list_workspace` 看本地文件 |
| 路径不安全，已拒绝 | 文件路径试图越界 | 检查路径不要含 `..` |
| 操作受限：xxx | 其他工具限制 | 看具体 reason 内容 |

### 4.3 失败时 LLM 怎么反应

LLM 拿到 `success=False` 的工具结果，会**自己调整**（换文件名、换工具）。如果它连续失败 5 次，会主动放弃并告诉你。

## 5. 20 轮用完怎么办

### 5.1 之前的问题

达到 MAX_ROUNDS 后，AgentLoop 直接退出，**用户看不到任何总结**。LLM 对最后工具的反馈变成"最后一句话"，让人误以为是答案。

### 5.2 现在的行为（v0.9.6 起）

达到 20 轮后：
1. 系统注入「禁止再调工具，直接给最终回答」指令
2. 追加一轮**纯对话调用**（不带 tools）
3. LLM 基于已有信息生成**总结回答**
4. 如果纯对话调用也失败（API 兼容性问题），显示兜底文案：

> ⚠️ 工具调用已用完预算（20 轮），无法继续。
> 建议：在新消息里直接问你想知道的 / 切换到「文档模式」生成完整报告

## 6. 减少 token 消耗的实战技巧

### 6.1 短问短答

❌ 差：「帮我分析一下 XXX 这个事」  
✅ 好：「XXX 的核心机制是什么？3 点」

### 6.2 引用而不是复述

❌ 差：把整个长文档粘进对话框让 AI 总结  
✅ 好：「用 read_workspace 读 workspace/xxx.md 帮我总结」

### 6.3 切文档模式生成长文

❌ 差：让 AI 在 chat 里"现场写 3000 字报告"  
✅ 好：切到 doc 模式，AI 会用 `write_workspace` + `set_doc_status` 流式生成产物

### 6.4 用 actionBar 一键复用

不要让 AI"再读一次当前回答"再生成报告——直接点 actionBar，AI 会**直接调用 set_doc_status**，省一轮。

## 7. 调试工具调用问题

如果工具频繁失败，看 server 日志：

```
[C:\Sidemate\data\logs\server.log] 搜 "[AGENT]"
```

关键日志：

| 日志 | 含义 |
|------|------|
| `[AGENT] === 第 N 轮 ===` | AI 第 N 轮推理开始 |
| `[AGENT] 工具调用: <name>(args)` | AI 决定调的工具 |
| `[AGENT] 工具 <name> 已达上限 N/M` | 工具触发硬限制 |
| `[AGENT] 子类超限，移除工具: [...]` | 工具被从列表移除 |
| `[AGENT] 达到最大轮次 20` | 触发收尾流程 |
