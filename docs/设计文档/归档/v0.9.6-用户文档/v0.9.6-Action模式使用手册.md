# Action 模式使用手册

> ✅ **本文档随 0.9.6 首发重发**（功能已在 0.9.6 完整发版）。
>
> 版本：v0.9.6 | 文件：`server/static/js/chat-actions.js`
> 适用人群：想精细控制 AI 行为 / 不同任务用不同提示词的用户

---

## 1. 什么是 Action 模式

Sidemate 的 Chat Tab 不止是「聊天」，还提供**针对不同任务的 Action 模式**。每个 Action 触发不同的后端处理逻辑、不同的提示词模板、不同的工具调用策略。

**Action 模式与三模式的关系**：

- **三模式**（离线/在线/并行）决定 **AI 在哪跑**（本地/云端/融合）
- **Action 模式**决定 **AI 干什么**（聊天/写文档/做总结/查知识库）

两者正交，可任意组合。

## 2. Action 列表

### 2.1 按模式分组

| Action | 离线 | 在线 | 并行 | 行为 |
|--------|:----:|:----:|:----:|------|
| `chat`（普通对话） | ✅ | ✅ | ❌ | 默认 Action，自由聊天 |
| `kb_qa`（知识库问答） | ✅ | ❌ | ✅ | 检索 KB 后回答 |
| `agent`（云端 Agent） | ❌ | ✅ | ❌ | 云端自动判断是否调用工具 |
| `doc`（写文档） | ✅ | ✅ | ❌ | 触发两阶段文档生成 |
| `research`（深度研究） | ✅ | ✅ | ❌ | 多源信息整合 |
| `summary`（做总结） | ✅ | ✅ | ❌ | 对长文本做摘要 |

### 2.2 在线模式快捷提示词

在线模式不直接列 Action 按钮，而是提供**快捷提示词**（`cloudPrompts`）：

| 按钮 | 提示词前缀 | 触发行为 |
|------|------------|----------|
| **联网搜索** | 「请联网搜索最新信息：」 | 云端 Agent 自动调用 `search_web` 工具 |
| **写文档** | 「请帮我撰写一份文档：」 | 触发 `doc` 流程（提纲 + 生成） |
| **深度分析** | 「请对以下内容进行深度分析：」 | 云端 Agent 启用 `fetch_url` 等深度工具 |

**行为特点**：

- 点击提示词按钮 → 自动填入引导词到输入框
- 再次点击同一按钮 → 取消选中，恢复原内容
- 点击其他按钮 → 切换提示词
- 用户手动编辑输入框 → 自动取消按钮选中（保留用户输入）
- `agent` Action 始终生效（不切）

### 2.3 离线模式 Action 列表

离线模式从后端 `/api/action/list` 拉取可用 Action，前端补充 `kb_qa` 按钮：

```js
// 离线模式自动追加知识库问答
actions.push({
  id: 'kb_qa',
  label: '知识库问答',
  title: '知识库问答 — 检索你的本地知识库，基于文档内容回答问题',
  icon_svg: iconSvg('books', '14')
});
```

**离线模式典型 Action**：

- `chat` —— 默认普通对话
- `kb_qa` —— 知识库问答（需要安装 KB 扩展包）
- `doc` —— 写文档（进入两阶段生成流程）
- `summary` —— 长文本总结
- 其他扩展 Action（按安装的 .sidemate 扩展决定）

### 2.4 并行模式 Action

并行模式**仅显示 `kb_qa` 按钮**（不可切换）：

```js
// 并行模式：仅知识库问答 + 齿轮开关
var kbBtn = document.createElement('button');
kbBtn.className = 'action-btn active';
kbBtn.setAttribute('data-action', 'kb_qa');
// ...
bar2.appendChild(kbBtn);
if (typeof _renderGearMenu === 'function') _renderGearMenu(bar2);
```

并行模式的 KB 问答会自动走四步时间线（检索→本地→云端→融合），与离线 KB 问答的最大区别是**有云端补充**。

## 3. Action 切换流程

### 3.1 触发切换

- 点击输入框上方的 Action 按钮组（`#actionBar`）
- 或选择提示词按钮（在线模式）

### 3.2 切换时行为

```js
async function setActionMode(mode, btn) {
  // 1. 拦截：正在生成时不允许切换
  if (typeof generating !== 'undefined' && generating) return;
  
  // 2. 清空文件引用（任何 Action 切换都清理）
  if (typeof clearFileRef === 'function') clearFileRef();
  if (typeof hideFileIndicator === 'function') hideFileIndicator();
  if (typeof clearPendingFile === 'function') clearPendingFile();
  
  // 3. 在线模式 agent 映射到 chat（后端 action_mode）
  var backendMode = mode;
  if (mode === 'agent') backendMode = 'chat';
  
  // 4. 调用后端切换 Action
  await fetch(API + '/api/action/switch', {
    method: 'POST',
    body: JSON.stringify({action: backendMode})
  });
  
  // 5. 更新全局状态 + UI 高亮 + placeholder
}
```

### 3.3 输入框 Placeholder 动态切换

每个 Action 有专属 placeholder 提示：

| Action | Placeholder |
|--------|-------------|
| `chat` | 「说点什么...」 |
| `agent` | 「问任何问题，AI 会自动搜索、阅读、回答...」 |
| `doc` | 「描述要生成的文档...」 |
| `research` | 「输入研究主题或问题...」 |
| 其他 | 「输入内容...」 |

### 3.4 缓存优化

`refreshActionBar()` 用 `_lastActionIds` 缓存机制避免重复渲染：

- 缓存 key 包含 `mode`（**P6 审计修复 M3**：修复切换模式后 ActionBar 不重渲染的 bug）
- 缓存 key 包含 action ID 列表
- 切换模式时强制清缓存重新渲染

## 4. 各 Action 详细行为

### 4.1 chat（普通对话）

- **后端 action_mode**：`chat`
- **行为**：直接走 `local_pipeline` / `cloud_pipeline` / `parallel_pipeline`
- **工具调用**：无（除非用户输入触发 Agent）
- **适用**：日常聊天、问答、闲聊

### 4.2 kb_qa（知识库问答）

- **后端 action_mode**：`kb_qa`
- **离线模式**：
  - 本地 LLM 检索 KB top-k chunk
  - 把 chunk 内容作为上下文注入 prompt
  - 答案严格基于 KB 内容
- **并行模式**：
  - 本地检索 + 本地生成
  - 云端基于本地摘要补充
  - 融合输出
- **适用**：基于 KB 资料回答问题

### 4.3 agent（云端 Agent）

- **后端 action_mode**：`chat`（agent 是 UI 概念）
- **行为**：云端 CloudEngine 接收 prompt 后，自主决定是否调用工具
- **工具**：`search_web` / `fetch_url` / `search_kb` / `summarize_history` / `write_section` / `calculator`
- **适用**：复杂任务（联网搜索 + 阅读 + 总结）

### 4.4 doc（写文档）

- **后端 action_mode**：`doc`
- **两阶段流程**：
  - **Phase 1**：生成 Markdown 提纲
  - **编辑/预览切换**：提纲在编辑栏中可自由修改
  - **Phase 2**：用户确认后，按提纲生成完整文档
- **UI**：提纲编辑器（系统字体 + 预览 + 刷新恢复）
- **输出**：.docx 文件
- **适用**：报告、文章、方案等长文档生成

### 4.5 summary（做总结）

- **后端 action_mode**：`summary`
- **行为**：上传文件后，对全文做摘要
- **典型场景**：长 PDF / 论文 / 报告 → 200 字摘要
- **触发**：v0.9.6 暂未提供独立 UI 入口，可通过提示词引导

### 4.6 research（深度研究）

- **后端 action_mode**：`research`
- **行为**：多源信息整合分析
- **适用**：市场调研、技术调研、对比分析

## 5. 提示词按钮（togglePromptChip）

### 5.1 核心逻辑

```js
function togglePromptChip(btn, promptText) {
  var input = document.getElementById('msgInput');
  if (!input) return;
  _promptSuppressSync = true;  // 抑制接下来的 input 事件
  
  if (_promptActiveBtn === btn) {
    // 再点同一个 → 取消选中，还原原文
    btn.classList.remove('active');
    input.value = _promptBackupText;
    input.dispatchEvent(new Event('input'));
    _promptActiveBtn = null;
    _promptBackupText = '';
  } else {
    // 取消之前选中的
    if (_promptActiveBtn) _promptActiveBtn.classList.remove('active');
    // 备份当前内容
    if (!(_promptActiveBtn && input.value === _promptActiveBtn.getAttribute('data-prompt'))) {
      _promptBackupText = input.value;
    }
    // 选中并填入
    btn.classList.add('active');
    btn.setAttribute('data-prompt', promptText);
    input.value = promptText;
    input.dispatchEvent(new Event('input'));
    input.focus();
    input.setSelectionRange(input.value.length, input.value.length);
    _promptActiveBtn = btn;
  }
}
```

### 5.2 关键行为

| 操作 | 行为 |
|------|------|
| 点击未选中按钮 | 填入提示词 + 按钮高亮 |
| 再次点击同一按钮 | 取消选中 + 还原原文 |
| 点击另一按钮 | 切换提示词 + 备份被替换前的原文 |
| 用户手动编辑 | 自动取消选中 + 保留用户输入 |
| 焦点回到输入框 | 光标定位到末尾 |

### 5.3 状态同步

- `_promptActiveBtn`：当前选中的按钮 DOM
- `_promptBackupText`：填入提示词前的原文备份
- `_promptSuppressSync`：抑制 input 事件触发的同步（避免误取消选中）

## 6. Action × 模式交叉表

| | 离线 | 在线 | 并行 |
|--|:----:|:----:|:----:|
| chat | ✅ 默认 | ✅ 默认 | ❌ |
| kb_qa | ✅ | ❌ | ✅ 强制 |
| agent | ❌ | ✅ 默认 | ❌ |
| doc | ✅ | ✅ | ❌ |
| summary | ✅ | ✅ | ❌ |
| research | ✅ | ✅ | ❌ |

**说明**：

- 并行模式只支持 KB 问答（其余 Action 隐藏）
- 在线模式的「联网搜索/写文档/深度分析」提示词按钮，**底层都走 agent Action**
- 离线模式可使用「查知识库」+「写文档」+ 其他 Action

## 7. 自定义 Action 提示词

v0.9.6 不提供 UI 自定义入口，但可通过以下方式添加：

### 7.1 临时方法（开发者）

修改 `server/static/js/chat-actions.js` 的 `cloudPrompts` 数组：

```js
var cloudPrompts = [
  { label: '联网搜索', tip: '请联网搜索最新信息：', icon: 'search' },
  { label: '写文档', tip: '请帮我撰写一份文档：', icon: 'write' },
  { label: '深度分析', tip: '请对以下内容进行深度分析：', icon: 'brain' },
  // 自定义：
  { label: '翻译成英文', tip: '请将以下内容翻译成英文：', icon: 'globe' }
];
```

### 7.2 扩展 Action

安装带 Action 扩展的 `.sidemate` 扩展包后，离线模式的 `/api/action/list` 会返回新增 Action。

## 8. 常见问题

### Q1：Action 按钮不见了？
- 切换模式时会重渲染 ActionBar，检查是否在 `agent` / `chat` 等 Action 中
- 检查后端 `/api/action/list` 是否正常返回
- 硬刷新 `Ctrl+Shift+R`

### Q2：Action 切换后输入框内容丢失？
- Action 切换会**主动清空文件引用**（`clearFileRef` / `clearPendingFile`）
- 提示词按钮的「取消选中」会还原**填入提示词前的原文**
- 如不希望丢失，**不要**点 Action 按钮

### Q3：写文档的提纲我修改了，刷新页面会丢吗？
不会。**v0.9.6 修复**了提纲刷新丢失问题：抽取共享函数 `_createDocConfirmBar()`，`renderMessages()` 末尾检测 `doc_phase:'outline'` 重建编辑器。详情见 `v0.9.6-新手指引使用手册.md` 第 4 节。

### Q4：知识库问答能跨 KB 吗？
**能**。kb_qa 检索所有 KB 文档（除非设置私密 + 无令牌），按相似度排序取 top-k。

### Q5：能否保存常用的 Action？
当前版本：可保存提示词（手动复制 / 收藏夹）。
v0.9.8 计划：自定义 Action 列表 + 保存提示词模板。

### Q6：Action 切换会清空历史吗？
**不会**。Action 只影响**下一条消息**的处理方式，历史消息保留。`memory_local` / `memory_cloud` 与 Action 无关。

### Q7：离线模式能联网吗？
**不能**。离线模式的 Agent 工具受限，`search_web` / `fetch_url` 不可用。Agent Action 仅在线模式可用。

### Q8：写文档能用 KB 资料吗？
**能**。在 KB 问答后追问「基于这些资料写一份报告」，会自动进入 doc 流程并把 KB 内容作为输入。
