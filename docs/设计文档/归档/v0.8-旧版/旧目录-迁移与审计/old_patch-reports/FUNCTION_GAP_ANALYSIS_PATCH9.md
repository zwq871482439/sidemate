## 二、功能差距分析（对标行业标杆）

### 🔴 重大差距（影响核心体验）

#### GAP-1: 无多模态能力（图片理解/生成）

**现状**: 
- 仅支持 OCR 文字提取（图片→文字）
- 不支持直接发送图片给模型进行理解
- 不支持图片生成

**对标**: 
- ChatGPT-4V / Claude 3 / 通义千问：支持图片输入理解
- Kimi / 豆包：支持图片输入

**影响**: 用户无法直接上传截图问"这张图什么意思"，必须依赖 OCR（准确率有限）

**建议**: 
- 短期：集成 Qwen-VL 或类似视觉模型
- 中期：支持图片+文字混合对话

---

#### GAP-2: 无联网搜索能力

**现状**:
- `cloud_provider.py` 有云端 API 支持，但无主动联网搜索
- Agent 可以调用搜索工具，但需要用户显式触发

**对标**:
- ChatGPT / Claude / 通义千问：内置联网搜索，自动判断是否需要
- Perplexity：搜索+总结是核心能力

**影响**: 无法回答"今天北京天气"、"最新新闻"等时效性问题

**建议**:
- 增加可选的搜索引擎集成（Bing API / SearXNG 自建）
- 在任务分类中增加 "search_needed" 判断

---

#### GAP-3: 无语音输入/输出（TTS）

**现状**:
- 录音模块只有 ASR（语音→文字）
- 无 TTS（文字→语音）能力

**对标**:
- ChatGPT App / 豆包：支持语音对话
- Kimi：支持语音输入

**影响**: 纪要功能只能看文字，无法听；不方便开车/走路时使用

**建议**:
- 集成 Edge-TTS 或本地 Piper TTS（轻量、离线）

---

#### GAP-4: 无文件导出/分享能力

**现状**:
- 对话记录可以保存为 JSON
- 无导出为 PDF / Word / Markdown 功能
- 无分享链接功能（合理，本地部署）

**对标**:
- ChatGPT：导出对话为 PDF/图片
- Notion AI：直接保存到文档

**影响**: 会议纪要生成后无法方便地导出给同事

**建议**:
- 增加导出为 Markdown / PDF 功能（前端可用 jsPDF 或 print-to-PDF）

---

### 🟡 中等差距（影响效率）

#### GAP-5: 对话历史管理简陋

**现状**:
- 仅支持按文件列表选择
- 无搜索、无标签、无文件夹分类
- 无对话重命名（默认按日期命名）

**对标**:
- ChatGPT：对话搜索、归档、文件夹
- Claude：项目(Projects)概念，可组织对话

**建议**:
- 增加对话搜索功能
- 支持对话标签/分类
- 支持自定义对话名称

---

#### GAP-6: 无提示词模板/快捷指令

**现状**:
- 场景选择器只有 chat/doc/code 三种
- 用户无法保存自定义提示词

**对标**:
- ChatGPT：GPTs / 自定义指令
- Claude：Projects 可设置系统提示
- 通义千问：百宝箱/快捷指令

**建议**:
- 增加"提示词市场"或"我的快捷指令"功能
- 允许用户保存常用 prompt 模板

---

#### GAP-7: 无协作/共享能力

**现状**:
- 纯单机使用
- 无多用户、无共享

**对标**:
- 所有云端产品都支持共享对话

**建议**:
- 短期内可导出对话文件分享
- 长期可考虑局域网多用户模式

---

#### GAP-8: 前端无代码高亮/复制按钮

**现状**:
- 代码块有基本样式，但无语法高亮
- 无"复制代码"按钮
- 无代码执行按钮（Agent 模式下有，但普通对话没有）

**对标**:
- ChatGPT / Claude：代码高亮 + 复制按钮
- Cursor：代码直接执行

**建议**:
- 集成 highlight.js 或 Prism.js
- 增加代码块操作按钮（复制、下载）

---

#### GAP-9: 无深色模式

**现状**:
- 只有浅色主题

**对标**:
- 所有主流产品都支持深色模式

**建议**:
- 增加深色主题（CSS 变量切换）

---

### 🟢 轻微差距（锦上添花）

#### GAP-10: 无键盘快捷键

**现状**:
- 只有 Enter 发送
- 无 Ctrl+K 搜索、Ctrl+N 新建对话等

**建议**:
- 增加常用快捷键

#### GAP-11: 无移动端适配

**现状**:
- viewport 已设置，但布局未针对移动端优化
- 输入框、按钮在手机上可能过小

**建议**:
- 增加响应式布局断点

#### GAP-12: 无使用统计/仪表盘

**现状**:
- 有基本统计（token 数、速度）
- 无累计使用量、趋势图表

**建议**:
- 增加个人使用仪表盘

## 三、用户体验痛点分析

### 痛点 1: 首次使用门槛高

**问题**:
- 需要手动下载模型、配置路径
- 知识库和 Whisper 需要额外安装扩展包
- 没有引导式首次配置向导

**优化建议**:
- 增加"首次启动向导"：检测环境 → 引导下载模型 → 测试运行
- 提供"一键安装脚本"

---

### 痛点 2: 模型加载/切换体验差

**问题**:
- 加载模型无进度显示（只有"加载中"）
- 切换设备需要重新加载模型
- 无模型推荐（根据硬件自动推荐）

**优化建议**:
- 增加模型加载进度条（从文件读取进度）
- 设备切换时保留模型状态（如果新设备支持）
- 根据检测到的硬件自动推荐最佳模型

---

### 痛点 3: 知识库使用流程复杂

**问题**:
- 三级状态机（未安装/已安装未加载/已激活）对用户来说太复杂
- 文档处理进度不透明
- 检索结果无相关性分数显示

**优化建议**:
- 简化状态：合并"已安装未加载"和"已激活"（懒加载）
- 文档处理增加详细进度（分块进度、嵌入进度）
- 检索结果显示相似度分数

---

### 痛点 4: 对话 Tab 和问答 Tab 功能重叠

**问题**:
- "对话"和"问答"两个 Tab 都可以上传文件、回答问题
- 用户不清楚什么时候用哪个

**优化建议**:
- 明确区分：对话=通用聊天，问答=基于知识库的专业问答
- 或合并为一个 Tab，通过模式切换区分

---

### 痛点 5: 错误提示不够友好

**问题**:
- 模型未加载时显示"请前往设置加载模型"
- 知识库处理失败只显示"处理失败"
- 无错误代码/排查指南

**优化建议**:
- 增加错误代码体系（如 E1001=模型未找到）
- 提供"一键诊断"按钮，自动检测常见问题
- 错误提示附带解决方案链接

---

### 痛点 6: 缺少"正在输入"状态

**问题**:
- 用户发送消息后，前端立即显示用户消息，但无"AI 正在思考"的即时反馈
- 直到第一个 token 返回才有反应

**优化建议**:
- 发送后立即显示"正在思考..."动画
- 增加队列位置提示（如果前面有任务）

---

### 痛点 7: 无对话分支/回溯

**问题**:
- 一旦发送消息，无法回到之前的某个点重新对话
- 只能新建对话从头开始

**对标**: Claude 的"分支对话"功能

**建议**:
- 增加"从这条消息重新开始"功能

---

### 痛点 8: 设置页面信息过载

**问题**:
- 设置 Tab 包含：模型、配置、资源、云端、训练、权限、审计、扩展
- 普通用户看到"训练"、"审计"会困惑

**优化建议**:
- 设置分级：基础设置 / 高级设置
- 或按用户角色显示不同设置项
