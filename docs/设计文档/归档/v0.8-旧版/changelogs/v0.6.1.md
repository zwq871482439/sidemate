## 二、版本号模块化管理

> 从"server 集中硬编码"改为"版本跟着模块走"，每个 .py 自己管自己的 `__version__`。

### 设计决策

**为什么不用微服务？** — 本地单用户应用，单进程模块化足够。微服务的服务发现、通信开销、部署复杂度在这个场景下完全是负收益。

**为什么版本跟着模块走？** — 更新某个模块时，版本号就在那个文件里，不需要去 server.py 同步。server 只通过 `__import__` 动态收集。

### 实现

```python
# 每个模块自己定义
__version__ = "v1.0"

# server.py 动态收集
@app.get("/api/info")
def api_info():
    modules = {}
    for mod_name in ("task_classifier", "response_filter", "cloud_provider",
                     "context_compressor", "pet_notebook", "models"):
        try:
            mod = __import__(mod_name)
            modules[mod_name] = getattr(mod, "__version__", "?")
        except ImportError:
            pass
    return {"version": f"{VERSION}.{VERSION_PATCH}", "modules": modules}
```

## 三、response_filter.py v1.0 重写

> 从 v0.1（只标注不修改）进化到 v1.0（标注 + 清理）

### 修复的 Bug

| Bug | 根因 | 修复方式 |
|-----|------|---------|
| 遍历中 `matches.remove(m)` | ConcurrentModification 经典 bug | 预计算 comment_lines set + string_ranges |
| `[一下二下的]?` 正则 | 字符类匹配单个字符而非"一下" | 改为 `(一下\|下\|一番)?` 分组 |
| 句子级删除误删内容 | `^(好的\|...).*?[。！？]` 贪婪匹配到有效内容 | 改为多轮词组级清理 |
| 残留标点 | 删完前缀后留下"。" | 最终 cleanup pass 清开头标点 |

### 新增功能

| 功能 | 说明 |
|------|------|
| 不完整输出检测 | 空回复 / 截断（末尾"的"/"了"/"着"） / 缺结尾标点 |
| N-gram 语义重复 | 3-gram Jaccard >0.6 → 重复段落标记 |
| 思考外泄分级 | 强信号（低阈值）+ 弱信号（高阈值），代码块排除 |
| 多轮前缀清理 | 第1轮删客套词 → 第2轮删分析前缀 → 第3轮清残留标点 |
| 未闭合 Markdown 粗体 | `**xxx` 缺配对检测 |

### 返回值不变

```python
def filter_response(text: str, model_name: str = "") -> dict:
    return {"text": ..., "warnings": [...], "has_issues": bool, "cleaned": str}
```

## 四、context_compressor.py v1.0 重写

> 从 v0.1（粗暴截断）进化到 v1.0（智能压缩）

### 关键改进

| 改进 | Before | After |
|------|--------|-------|
| 代码注释处理 | 不区分 # 在字符串内外 | 安全区分，保留 docstring/装饰器/TODO/FIXME |
| 保留行 | 无特殊处理 | def/class/return/raise/yield/import 行完整保留 |
| 文本关键词 | 仅中文 | +英文关键词 + 废话句过滤 |
| 压缩顺序 | `insert(0)` O(n²) | `append` + `reverse` O(n) |
| 极端压缩 | 无 | `_make_one_line_summary()` |
| 代码块判定 | >50% 算代码 | >40% 算代码（更灵敏） |
| 受保护轮次 | 无 | 最近 2 轮完整保留不压缩 |
| 压缩率日志 | 无 | 显示 "压缩率: 45.2%" |

### 代码注释安全剥离

核心逻辑：先扫描字符串字面量范围（`'...'`/`"..."`/`"""..."""`），再判断 `#` 是否在字符串内。字符串内的 `#` 不当注释处理。
