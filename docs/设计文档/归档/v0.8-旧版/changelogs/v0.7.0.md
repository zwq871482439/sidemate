## 一、前端重构：Gradio -> 原生 SPA

> 从 Gradio 6.13 迁移到纯原生 HTML/CSS/JS 单页应用，消除 Gradio 渲染死锁、CDN 依赖、启动卡顿等问题。

### 动机

| 问题 | 根因 |
|------|------|
| 页面冻结/空白 | `init()` 中 5 个串行 fetch 无超时，后端未启动时无限挂起 |
| CDN 不可达 | KaTeX 从 cdn.jsdelivr.net 加载，纯内网环境无法访问 |
| Gradio Tab 渲染死锁 | Gradio 6 MutationObserver 冲突，无法代码层面修复 |
| 巨型单文件 | 5749 行 index.html，CSS/JS/HTML 混杂 |

### 技术选型

| 领域 | 选型 | 理由 |
|------|------|------|
| 框架 | 纯原生 HTML/CSS/JS | 内网环境，无构建工具依赖 |
| 模块化 | ES Module（`<script type="module">`） | 原生支持，无需构建工具 |
| 状态管理 | 全局 `AppState` 对象 + `EventTarget` 事件 | 轻量级，无需引入框架 |
| 错误通知 | 自实现 Toast + Banner 组件 | 无外部依赖 |
| KaTeX | 本地文件引入（katex.min.js + katex.min.css） | 无外网依赖 |

### 核心改进

| 改进 | Before (Gradio) | After (原生 SPA) |
|------|-----------------|------------------|
| init() | 5 个串行 fetch 无超时 | Promise.allSettled 并行 + 8s 超时 |
| fetch 超时 | 122 处无超时 | fetchWithTimeout 封装，默认 10s |
| 离线体验 | 空白页面 | 3s 内显示降级 UI + 重试按钮 |
| 错误提示 | 34 处空 catch | 统一 Toast + Banner 通知 |
| CDN 依赖 | KaTeX 外网加载 | 本地 static/vendor/ 引入 |
| SSE 流式 | Gradio generator | 原生 EventSource / fetch 流式读取 |
| KaTeX 渲染 | CDN 加载 | 本地引入 + 降级策略（加载失败以源码显示） |
| 离线检测 | 无 | 30s 心跳 + 红色横幅 + 重试按钮 |

## 三、Skill 系统

> 离线优先的技能框架，统一 ZIP 打包规范。

### 设计原则

1. **离线优先**：Skill 由安装人员 ZIP 导入，无需外网
2. **脚本化**：文件操作脚本化，避免小模型误操作
3. **输出 Word**：面向非开发人员，输出 .docx
4. **分段读取**：小模型上下文有限，大文档分段处理

### Skill ZIP 规范

```
skills/my-skill/
+-- skill.json    # 元数据（必须）
+-- main.py       # 入口脚本（必须）
+-- README.md     # 说明（可选）
+-- assets/       # 资源（可选）
```

### v0.7 基础技能

| 技能 | 功能 |
|------|------|
| 文件操作 | 列出/搜索/读取（白名单安全，禁止删除/移动） |
| Word 读取 | 分段策略：前 2000 字 + 尾 500 字 + 标题摘要 |
| Word 生成 | 模板驱动生成 .docx |

## 四、fetchWithTimeout 封装

### 核心 API

```javascript
async function fetchWithTimeout(url, options, timeout = 10000) {
  const controller = new AbortController();
  const id = setTimeout(() => controller.abort(), timeout);
  // ...
}
```

### 策略

- 默认超时 10 秒，init 阶段 8 秒
- SSE 流式请求不使用 fetchWithTimeout（保持原有读取超时逻辑）
- 错误分级：网络不可达 / 服务端错误 / 业务错误 / 未知

## 五、init() 并行化

### 改造前

```
refreshStatus() --> loadCloudConfig() --> loadPermStatus() --> loadChatList() --> fetch chats
（串行，一个卡住全部阻塞）
```

### 改造后

```
Promise.allSettled([
  refreshStatus(),     // 内部也已并行化（5 个 API 并行）
  loadCloudConfig(),
  loadPermStatus()
]) --> loadChatList() --> fetch chats --> renderMessages()
```

- 任一请求失败不阻塞其他
- 全部失败时显示离线降级 UI
- refreshStatus 内部 5 个 API 也并行化

## 七、设计决策

| 决策 | 理由 |
|------|------|
| 不用前端框架 | 内网环境、无构建工具依赖、团队熟悉度 |
| ES Module 而非 bundler | Phase 1/2 保持原生 JS，Phase 3 再引入 Vite |
| AppState + EventTarget | 轻量级状态管理，收敛全局变量 |
| HTML onclick 兼容 | 保持 `window.xxx = fn` 暴露，最小改动 |
| KaTeX 降级 | 加载失败时公式以源码显示，不阻塞页面 |
| monkey-patch fetch | 快速覆盖 122 处 fetch 超时，后续逐模块迁移 |
