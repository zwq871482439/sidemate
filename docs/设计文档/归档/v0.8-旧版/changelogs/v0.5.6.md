# v0.5.6 变更记录

## 压缩触发机制重构

### 问题
- 之前按**轮次**触发压缩，但不同模型的响应长度差异巨大（1.5B 可能输出 200 字，8B 输出 2000 字）
- 6 轮对话在 8B 模型下可能远超上下文限制，而 1.5B 模型可能还很空

### 改动
- **触发条件**：从 `rounds > max_rounds + 2` 改为 `total_chars > max_history_chars * 0.8`
- **保留策略**：从"保留最近 N 轮"改为"保留最近 max_history_chars * 0.4 字符的原始消息"
- **前端提示**：压缩发生时 SSE 新增 `compress` 事件，前端显示"正在压缩旧对话..."提示（3 秒后消失）
- **返回值**：`_update_session_cache()` 返回 `(cache_text, did_compress)` 元组

### 涉及文件
| 文件 | 改动 |
|------|------|
| `server.py` | `_update_session_cache()` 重写，版本号 0.5.5 → 0.5.6 |
| `index.html` | 新增 `compress` SSE 事件处理 + CSS 动画 |

## v0.7 Skill 架构设计（文档层面）

### 核心设计原则
1. **离线优先**：Skill 和模型都由安装人员负责安装，网页只需要一个"导入 ZIP"按钮
2. **脚本化**：小模型不靠谱，文件操作必须脚本化，避免误操作
3. **输出 Word**：非开发人员不会用 Markdown，必须输出 .docx
4. **分段读取**：小模型上下文有限，50 页 Word 全文塞进去会爆

### Skill ZIP 打包规范
```
skills/my-skill/
├── skill.json    # 元数据（必须）
├── main.py       # 入口脚本（必须）
├── README.md     # 说明（可选）
└── assets/       # 资源（可选）
```

### v0.7 基础技能
1. **文件操作** — 列出/搜索/读取（白名单安全，禁止删除/移动）
2. **Word 读取** — 分段策略：前 2000 字 + 尾 500 字 + 标题摘要
3. **Word 生成** — 模板驱动生成 .docx

### ROADMAP 变更
- v0.7 从"角色面板 + Word"改为"角色面板 + Skill 系统（离线优先）"
- v0.8 去掉了 Skill 文件操作（已移到 v0.7）
- 三层记忆架构描述更新为"按字符数触发"

## 模型 ZIP 导入机制（v0.6 前置）

### 需求
- v0.6 的模型导入需要和 v0.7 Skill 导入统一的机制
- 安装人员在网页上提交 ZIP，程序自动识别并解压到 models/ 目录
- 导入过程要有进度显示

### 改动
- **后端 API**：新增 `POST /api/models/import`
  - 接收 ZIP 文件上传
  - 校验 ZIP 内是否包含 `openvino_model.bin`
  - 支持两种 ZIP 结构：目录 ZIP（推荐）和扁平 ZIP
  - SSE 流式返回进度（上传→验证→解压→注册）
  - 解压完成后自动扫描注册模型
  - 已存在同名目录自动覆盖
- **前端 UI**：设置页新增"导入模型"区域
  - 文件选择器（.zip）
  - 进度条 + 步骤文字
  - 成功/失败结果提示
  - 导入成功自动刷新模型列表

### 涉及文件
| 文件 | 改动 |
|------|------|
| `server.py` | 新增 `api_models_import()` 端点，import 增加 `zipfile, shutil, tempfile` |
| `index.html` | 设置页新增导入模型区域（按钮+进度条），新增 `importModelZip()` JS 函数 |
| `ROADMAP.md` | v0.6 增加模型 ZIP 导入 + 打包规范 + 流程图，v15 |
