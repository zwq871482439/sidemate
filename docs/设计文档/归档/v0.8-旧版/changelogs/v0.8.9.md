## 一、Pipeline DAG 编排引擎

### 设计理念

8B 模型不擅长复杂多步推理，但擅长简单原子操作。Pipeline 将复杂任务拆解为 DAG 步骤，Python 负责编排，每步 LLM 调用都是"蚂蚁级"简单任务。

### 核心组件

| 文件 | 职责 |
|------|------|
| `pipeline/engine.py` | DAG 执行器（~300行）：拓扑排序、顺序/并行执行、暂停/恢复/取消 |
| `pipeline/context.py` | 运行时上下文（~80行）：变量系统、Step 输出存储 |
| `pipeline/steps.py` | Step 执行器（~200行）：`_execute_llm()` / `_execute_code()` / `_execute_tool()` |
| `pipeline/templates.py` | 模板加载器（~60行）：从 JSON 加载 PipelineTemplate |

### 内置 Pipeline 模板

| Pipeline | 场景 | 步骤 |
|----------|------|------|
| `write_doc` | 文档写作 | 解析意图 → KB 检索 → 生成大纲 → 并行撰写 → 组装 → 审阅 |
| `analyze_doc` | 文档分析 | 提取文本 → 分块 → 并行提取要点 → 合并去重 → 生成摘要 |
| `write_code` | 代码编写 | 解析需求 → 设计接口 → 生成代码 → 代码审查 |

### SSE 事件协议

新增 `pipeline_*` 前缀事件：`pipeline_start` / `pipeline_step` / `pipeline_progress` / `pipeline_done` / `pipeline_error` / `pipeline_paused` / `human_approval`

### 用户干预

- 暂停/恢复：任意时刻暂停 Pipeline，当前 Step 完成后停止
- 取消：立即终止 Pipeline，释放资源
- 人工审批：Step 配置 `human_approval` 时暂停等待用户选择

## 二、server.py Router 拆分

将 3950 行的 `server.py` 拆分为 6 个 FastAPI Router 模块，所有 API 路径签名不变。

| Router | 文件 | 端点数 | 前缀 |
|--------|------|--------|------|
| ChatRouter | `routers/chat.py` | ~20 | /api/chat/*, /api/qa/* |
| KBRouter | `routers/kb.py` | ~19 | /api/kb/* |
| RecorderRouter | `routers/recorder.py` | ~24 | /api/recorder/* |
| SettingsRouter | `routers/settings.py` | ~20 | /api/models, /api/config |
| NotebookRouter | `routers/notebook.py` | ~6 | /api/notebook/* |
| SkillRouter | `routers/skill.py` | ~5 | /api/skill/* |

`server.py` 精简为 ~200 行（初始化 + Router 注册），通过 `routers/deps.py` 依赖注入共享服务实例。

## 三、统一上传按钮

将 `📷` 图片上传和文档上传合并为 `➕` 按钮，后端根据文件扩展名自动路由：

- 图片（.png/.jpg/...） → OCR 提取文本
- 文档（.pdf/.docx/...） → 触发 `analyze_doc` Pipeline
- 音频（.mp3/.wav/...） → 路由到录音 Tab
