## 3. 需求详细描述

### 3.0 Bug 修复（P0）

#### 3.0a `chunking_orchestrator.py` 传递未支持参数 `stream=True`

**问题**: `chunking_orchestrator.py:264` 调用 `chat_stream()` 时传递了 `stream=True` 参数，但 `chat_stream()` 签名中没有此参数，会导致 `TypeError` 崩溃。

**修复方案**: 移除 `stream=True` 参数。

**涉及文件**: `chunking_orchestrator.py`

#### 3.0b `_stop_generation` 竞态条件

**问题**: `models.py` 和 `routers/chat.py` 中多处直接读写 `_stop_generation` 全局标志，无锁保护，高并发下可能丢失 stop 信号。

**修复方案**: 
- 所有读写通过统一方法（带锁的 property）
- 或确保所有赋值操作都使用 `_stop_lock`

**涉及文件**: `models.py`, `routers/chat.py`

### 3.1 Agent 智能化改进（P1）

#### 用户故事
- 作为办公用户，我希望 Agent 能更准确地判断何时调用工具，减少空转和无效循环，从而提高任务完成效率。

#### 验收标准
1. Agent 工具调用成功率 ≥ 80%（当前基线待测）
2. think 标签内不再包含工具调用代码
3. 单次用户请求的工具调用循环次数 ≤ 3 次
4. 失败重试机制：格式错误时自动修复并重试，最多 2 次

#### 技术方案建议
- **Prompt 工程**：
  - 在 system prompt 中明确区分 "思考过程" 和 "工具调用" 的边界
  - 增加 few-shot 示例，展示正确的 think → tool_call 流程
  - 使用 `<think>...</think>` 和 `<tool_call>...</tool_call>` 明确标签约束
- **工具选择策略**：
  - 增加工具描述的质量（更清晰的 name/description/parameters）
  - 引入工具选择预判断：让模型先输出 `need_tool: yes/no`，再决定调用
- **失败重试机制**：
  - 保留现有容错（中文括号→英文、补全 JSON、猜测意图）
  - 增加重试计数器，超过阈值后返回友好错误提示
- **后处理增强**：
  - 从 think 标签中提取误放的 tool_call，自动纠正

#### 涉及文件
- 后端：`agent/core.py`, `agent/prompts.py`, `agent/tool_parser.py`
- 可能新增：`agent/retry_handler.py`

#### 3.2c 模型加载进度条（P0）

**用户故事**

    - 10%：开始加载，验证模型文件
    - 50%：模型权重加载中
    - 90%：OpenVINO 编译/优化中
    - 100%：加载完成，就绪
- **前端**：
  - 订阅 SSE 端点，实时更新进度条
  - 使用 MUI LinearProgress 或自定义进度条组件

### 3.3 设置 Tab 重构（P0）

#### 3.3a 统一扩展安装接口（P0）

**用户故事**
- 作为用户，我希望在一个地方管理所有功能模块的安装，安装后自动解锁对应 Tab，不需要手动配置。

**验收标准**
1. 设置 Tab 新增"扩展中心"面板
2. 支持上传 ZIP 文件，自动解压到对应目录：
   - 模型 ZIP → `models/` 目录 → 解锁"对话"Tab

  ```json
    "entry_point": "...",
    "dependencies": []
  }
  ```
- 前端根据已安装扩展动态渲染 Tab（路由守卫/条件渲染）

**涉及文件**

### 3.9 PPT 读写评估（P2 — 本期仅评估）

#### 评估结论

| 维度 | 评估结果 |
|------|----------|
| **8B 模型处理 PPT 可行性** | ⚠️ 有限可行。PPT 是结构化演示文档，8B 模型可理解文本内容，但难以处理复杂版式、图表、动画逻辑。 |
| **技术方案** | 使用 `python-pptx` 库读取 `.pptx` 文件，提取文本框内容。不支持 `.ppt`（旧格式）。 |
| **KB 集成** | 可将 PPT 每页文本提取后分块存入 KB，作为问答素材。 |
| **对话集成** | 用户选择 PPT 后，提取文本作为上下文输入模型。 |
| **建议** | **本期不实现**。理由：1) 8B 模型对 PPT 结构化内容理解能力有限；2) `python-pptx` 提取的纯文本丢失大量版式信息；3) 用户核心场景（办公文档）已被 Word/Excel/TXT 覆盖。建议放到 Patch12+ 评估。 |

#### 技术预研
- `python-pptx` 安装：`pip install python-pptx`
- 提取示例：
  ```python
  from pptx import Presentation
  prs = Presentation('file.pptx')
  for slide in prs.slides:
      for shape in slide.shapes:
          if hasattr(shape, "text"):
              print(shape.text)
  ```

### 3.10 Excel 写入评估（P2 — 本期仅评估）

#### 评估结论

| 维度 | 评估结果 |
|------|----------|
| **8B 模型生成表格数据质量** | ⚠️ 中等。模型可生成结构化 JSON/CSV 数据，但复杂公式、多 Sheet 关联、数据验证等容易出错。 |
| **技术方案** | 使用 `openpyxl` 库写入 `.xlsx` 文件。支持单元格写入、样式、公式。 |
| **使用场景** | 1) Agent 生成报表后写入 Excel；2) 用户要求"把数据整理成表格"；3) 会议纪要提取待办事项写入表格。 |
| **风险** | 模型可能生成格式错误的数据（如日期格式、数字文本混用），需要后处理校验。 |
| **建议** | **本期不实现，但预留接口**。理由：1) 写入场景不如读取场景明确；2) 数据质量风险高，需大量测试；3) 可先实现 Excel 读取（Patch9 已有），写入放到 Patch11 评估。 |

#### 技术预研
- `openpyxl` 安装：`pip install openpyxl`
- 写入示例：
  ```python
  from openpyxl import Workbook
  wb = Workbook()
  ws = wb.active
  ws['A1'] = 'Hello'
  wb.save('output.xlsx')
  ```

## 5. 风险与依赖

### 5.1 技术风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| Agent 改进效果不达预期 | P1 核心体验 | 设定可量化的基线指标，预留 2 轮迭代调优时间 |
| SSE 进度推送与前端兼容 | P0 进度条 | 测试主流浏览器 SSE 支持，准备轮询降级方案 |
| 扩展 ZIP 包安全（恶意文件） | P0 扩展中心 | 限制 ZIP 内文件类型，解压路径白名单，禁止执行权限 |
| 深色模式 CSS 覆盖不全 | P0 深色模式 | 建立设计令牌（Design Token），全量扫描组件 |

### 5.2 依赖关系

```
3.3a 统一扩展安装接口
    ├── 3.4 知识库状态机简化（依赖扩展安装接口）
    ├── 3.6 对话文件选择从 KB（依赖 KB 可用性）
    └── 3.3b 删除未使用功能（可并行）

2c 模型加载进度条
    └── 需要后端 SSE 接口 + 前端进度组件

3.7 取消 web-search
    └── 1 Agent 智能化改进（需确认 Agent 不再引用搜索工具）
```

### 5.3 资源依赖

- **前端**：需引入 `highlight.js`（或 `Prism.js`）、`docx` 库
- **后端**：SSE 进度推送需调整模型加载逻辑，增加回调点
- **设计**：深色模式需定义完整色板（建议 8-10 个核心变量）
