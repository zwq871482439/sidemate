# v0.5.4 变更记录 (2026-04-30)

## 背景
用户测试 _001.json 发现：
- 第一次（写井字棋）：代码基本完整，但 `board[关心]` 是幻觉（中文替代变量名）
- 第二次（修 bug）：分析了一大段废话后截断，代码块为空

## 改动

### 1. 新增 `response_filter.py` — 响应过滤器
- **代码幻觉检测**：代码块中中文字符作为变量名（如 `board[关心]`、`def 函数`）
- **未闭合结构检测**：未闭合代码块、括号不平衡
- **思考外泄检测**：正文中"让我先分析"、"我需要检查"等自言自语 ≥3 处
- **重复段落检测**：连续 3+ 行相同文本
- 结果不修改原文本，只标注警告，前端显示黄色 ⚠️ 标签

### 2. `models.py` — System Prompt 优化
旧（1 句笼统）：
```
用中文简洁回答。直接给出答案，不要重复问题。
```

新（4 条硬规则）：
```
1. 直接给出答案或代码，不要复述问题，不要自我分析推理过程
2. 写代码时：只用ASCII变量名和英文注释，绝不使用中文作为代码变量/函数名/键名
3. 修bug时：直接给出修改后的完整代码，不要解释哪里错了
4. 回答尽量简短，能用代码说清楚的不要用文字
```

### 3. `server.py` — 截断检测增强
新增检测规则：
- 空代码块：````` \n ````` 模式（模型开了代码块但没写内容就停了）
- 尾部空块：最后 50 字符内有 `````\n`````
- 自言自语结尾："应该是："/"如下："后没有实际内容
- 检测阈值降低：50→30 字起检
- 非流式 max_tokens：512→4096

### 4. `server.py` + `index.html` — 过滤器集成
- SSE 新增 `filter` 事件类型
- 生成结束后运行 `filter_response()`，有警告时前端渲染黄色标签
- 版本号：0.5.3 → 0.5.4

## 通用性说明
- System prompt 规则对所有 Qwen3 系列通用（0.6B~14B）
- `response_filter.py` 是纯文本分析，不依赖特定模型
- 截断检测基于 markdown 语法特征，与模型无关
