## 二、核心 patch：记忆 Tab 独立（#10）

> **优先级：P1**
> **预估工作量：1h**

### 现状问题

- `tab-knowledge` 叫"知识库"，但知识库里混着角色面板、用户画像、facts 列表、glossary 字典
- facts（列表）和 glossary（字典）是同一种数据的两种形态，底层两套独立存储，用户感知不统一
- 前端无统一记忆管理界面，不支持手动增/删/改

### 改进方案

**前端**：
- `tab-knowledge` 改名为"记忆"
- 统一列表展示所有 memory 条目（fact 类型和 term 类型统一渲染）
- 支持手动新增/删除/编辑
- 保留批量导入入口（`术语=解释` 格式）
- 按来源筛选（对话提取/即时纠正/手动添加/批量导入）

**后端**：
- `pet_notebook.py`：将 facts + glossary 两套存储合并为统一 `memory` 列表
- `server.py`：新增 `/api/notebook/memory` CRUD 接口
- 不改变注入格式（term 类型仍以 `术语 = 解释` 注入）

**JSON 结构**：
```json
{
  "memory": [
    {"type": "fact", "content": "用户叫 slow，住在北京", "source": "对话提取", "date": "2026-05-17"},
    {"type": "term", "term": "ABC", "definition": "公司内部自动化测试框架", "source": "手动添加", "date": "2026-05-17"},
    {"type": "fact", "content": "用户偏好简洁回答", "source": "即时纠正", "date": "2026-05-17"}
  ]
}
```

## 三、核心 patch：离线赋能与在线补课机制（新增）

> **优先级：P1**
> **预估工作量：4-6h**
> **核心设计原则**：离线优先，云端仅作批量补课，不做实时干预

### 背景问题

v0.8 patch 1-3 已实现：Skill 系统、权限、审计、角色面板、训练管理、反馈机制、离线压缩。
**缺的核心能力**：学生模型（本地）如何从自己的历史行为和云端教师（在线）那里学到东西。

### 架构设计

```
┌─────────────────────────────────────────────────────────┐
│                   学生模型（本地，离线默认）               │
│  ┌─────────────┐  ┌──────────────┐  ┌───────────────┐ │
│  │正向范例固化  │  │  离线自审压缩  │  │ 记忆注入增强  │ │
│  │(实时发生)   │  │  (压缩时触发)  │  │(每次对话)    │ │
│  └─────────────┘  └──────────────┘  └───────────────┘ │
└──────────────────────────┬──────────────────────────────┘
                           │ 用户点赞/踩     │ 上下文压缩触发
                    ┌──────┴──────────────────┬────────────┐
                    │         记忆层 (memory)              │
                    │  来源：对话提取/即时纠正/正向范例       │
                    │        /批量导入/在线补课(云端)        │
                    └─────────────────────────┬────────────┘
                                              │
                                      在线模式切换时
                                              │
                                     ┌────────┴────────┐
                                     │   云端教师(在线)  │
                                     │  批量补课/错误提炼 │
                                     │ (不实时干预对话)  │
                                     └─────────────────┘
```

### 功能 1：正向范例固化（离线，实时）

- **触发**：用户点击"赞"时，自动将该 QA 对标记为正向范例
- **存储**：写入 `memory`（新增 `type: "good_answer"`，含 `question` + `answer` + `scenario` + `date`）
- **注入**：每次对话 system prompt 注入时，随机选 1 条正向范例作为上下文参考
- **工程文件**：`feedback.py`（赞时写 memory）、`pet_notebook.py`（注入逻辑）、`models.py`（prompt 拼接）

### 功能 2：踩反馈结构化（离线，实时）

- **触发**：用户点击"踩"时，弹出原因选项（多选）：
  - "答非所问"
  - "信息错误"
  - "不完整"
  - "风格不喜欢"
  - "其他（请输入）"
- **存储**：`feedback.json` 中新增 `reason` 字段，结构化存储

### 功能 3：本地自审压缩模板（离线，压缩时）

- **触发**：`context_compressor.py` 执行压缩时（8B+ 模型）
- **改动**：压缩 prompt 升级为结构化自审，1.5B 模型降级为普通摘要
- **注意**：1.5B 模型自审能力有限，仅 8B+ 触发此功能

### 功能 4：会话复盘补课（在线，切换时触发）

- **触发**：用户从离线切换到在线模式时
- **交互**：弹窗提示——"检测到 N 条踩反馈 + M 轮对话未复盘，是否启动云端补课？"
- **云端教师做的事**：
  1. 读取离线期间积累的踩反馈记录（含结构化原因）
  2. 读取未压缩的 session 历史
  3. 输出：一份"学生模型典型错误模式"清单（按问题类型分类）
- **写入**：`memory`（source=`在线补课`）
- **工程文件**：新增 `online_review()` 函数或独立 `review_session.py`

### 功能 5：记忆注入增强（离线，每次对话）

- **现状**：memory 静态注入，无差异化
- **改动**：按 task_classifier 结果（text/reasoning/code）从 memory 中选最相关的正向范例优先注入
- **简化实现**：不做复杂排序，只是正向范例权重提高（注入时多带 1 条）

## 六、Excel/CSV 提取为独立 Skill（#19，架构对齐）

> **优先级：P2**
> **预估工作量：1h**

### 现状问题

Excel/CSV 读取已实现，但内嵌在 `server.py` 的 `_read_excel()`，不是独立 Skill。无权限检查、无审计日志，与 `doc_reader.py`（Word 读取，是独立 Skill）架构不一致。

### 改进方案

将 Excel/CSV 读取提取为独立 Skill `excel_reader.py`，与 `doc_reader.py` 对齐：
- 独立 Skill → 有权限检查、有审计日志
- 新增 `/api/skill/excel_reader` 接口
- 前端调用方式与其他 Skill 统一
