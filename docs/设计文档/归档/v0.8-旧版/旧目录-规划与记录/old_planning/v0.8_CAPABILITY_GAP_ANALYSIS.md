# v0.8 功能实用性缺口分析（Patch 4）

> 分析角度：作为 slow 的本地办公 AI 助手，当前已实现的 vs 实际办公场景需要的
> 目标：找出真正缺什么、哪些多余、哪些能改进
> 版本：v0.8 patch 4（基于 patch 1-3 完成后的问题分析）
> 更新：2026-05-17（新增"离线赋能与在线补课"机制设计）

---

## 一、核心痛点的拆解

你的原话：
> 想要 AI 辅助办公但不想把数据上传云端 → 解决方案：小模型+智能体，本地完成日常办公任务

**这个痛点可以拆成三层：**

| 层次 | 需求 | 当前解决程度 |
|------|------|-------------|
| 第一层：安全底线 | 数据绝对不出本机 | ★★★★★ 已实现 |
| 第二层：基本可用 | 能完成日常办公的 X% | ★★★☆☆ 约 50% |
| 第三层：效率提升 | 比不用 AI 明显更快更好 | ★★☆☆☆ 有提升但不够 |

## 二、真实办公场景逐个过

### 场景 1：读一份公司报告/文件

| 文件类型 | 能否处理 | 实际体验 | 缺口 |
|----------|---------|---------|------|
| Word (.docx) | **能** | 独立 Skill（doc_reader.py），分段+表格，够用 | 缺样式渲染 |
| Excel (.xlsx) | **能** | server.py 内嵌 `_read_excel()`，支持多 sheet，最多 50 行 | **架构不一致**（不是 Skill，无权限/审计） |
| PDF | **不能** | 没这功能 | **最大缺口** |
| PPT (.pptx) | **不能** | 没这功能 | ⚠️ 8B 模型理解 PPT 能力存疑 |
| CSV | **能** | server.py 内嵌读取 | 同 Excel，架构不一致 |
| 图片里的文字 | **能** | OCR 识别后传入对话 | 够用 |
| 网页文章 | **能** | web-reader Skill（已实现） | — |

### 场景 3：录音纪要

**技术方案：分块缓冲准实时转录**

```
录音中（MediaRecorder API，浏览器原生）
    ↓ 每10-30秒切一块
    → 投入 Whisper 处理队列（异步）
    → 结果陆续返回（有几秒延迟）
    → 前端滚动显示"实时预览"
    ↓ 停止录音
    → [下载文字稿] + [交给AI总结]
```

- 全程本地，不上云
- 浏览器原生 API，不需要任何外部依赖
- 有延迟的准实时，不是零延迟但能看到文字慢慢出来

## 三、现有 Prompt 双引擎体系（不动）

现有机器端模块（不做调整）：

| 模块 | 文件 | 功能 |
|------|------|------|
| 任务分类器 | `task_classifier.py` | 判断类型（text/reasoning/code），v7版本 |
| 场景模式 | `server.py` | 用户手动选：对话/搜索/文档/研究/代码 |
| 响应过滤器 | `response_filter.py` | 7个检测器（幻觉/思考外泄/重复/截断/空洞/格式/指令偏离） |

**两层架构**：
```
第一层：场景模式（用户手动选）
  对话 / 搜索 / 文档 / 研究 / 代码
  ↓
第二层：task_classifier（代码自动判断）
  text / reasoning / code/agent
  ↓
各自对应不同的 think_instruction（深思考 vs 不思考）
```

**不做的事**（已取消）：
- ❌ Prompt 模板编辑器（与现有体系重叠，增加复杂度）
- ❌ Prompt 模板库（与分类器抢活）

## 四、用户参与的反馈优化（仅保留即时纠正）

现有反馈（赞/踩）只是记录，用户感知不到变化。

### 即时纠正（保留，patch 4 核心）

```
用户看到 AI 回复中某段话不对
  → 选中这段文字
  → 点击"这里不对，应该XXX"
  → 保存到个人记忆（统一 memory 列表）
  → 下次遇到类似场景，AI 会参考
```

**与现有体系的区别**：
- 不改 system prompt，不改分类器
- 只是把纠正内容存入记忆，依赖记忆注入机制生效

---

### 三种方式的对比

| 方式 | 轻量程度 | 效果 | 状态 |
|------|---------|------|------|
| 即时纠正（存记忆） | ★★★★★ | 直接改善具体回答 | **保留 patch 4** |
| 记忆 Tab 手动管理 | ★★★★☆ | 长期积累、可编辑删除 | **保留 patch 4** |
| 反馈 → Prompt 学习 | ★★★☆☆ | 需要人工分析，投入产出比一般 | **合并入反馈细分类** |

## 八、离线赋能与在线补课机制（Patch 4 核心设计）

> **设计日期：2026-05-17**
> **核心原则：离线优先，云端仅作批量补课，不做实时干预**

### 7.1 背景问题

当前系统已有：
- ✅ 反馈系统（赞/踩）—— 积累了大量"用户觉得好的回答"
- ✅ 上下文压缩（context_compressor）—— 定期压缩旧对话
- ✅ 小册子 memory —— 提取关键知识
- ✅ 在线/离线切换 —— 云端模型可用

**缺的**：这套机制没有形成闭环，学生模型从自己的历史行为里学到的东西很有限。

### 7.2 赋能的两个维度

| 维度 | 触发条件 | 是否需要云端 | 机制 |
|------|---------|------------|------|
| **离线自我提升** | 任何时候 | ❌ 不需要 | 从自身反馈和压缩行为中提取知识 |
| **在线批量补课** | 切换到在线模式时 | ✅ 需要 | 云端教师分析离线积累的问题模式 |

### 7.3 离线自我提升三路径

#### 路径 1：正向范例固化（实时，最简单）

```
用户点"赞"
    ↓
那段 QA 对自动标记为正向范例
    ↓
写入 memory（type: "good_answer"，含 question + answer）
    ↓
下次对话 system prompt 注入时，随机带 1 条正向范例
    ↓
遇到类似问题时，本地模型有"见过类似好答案"的语境
```

**优点**：完全不依赖云端，实时发生，用户立刻感知到效果
**存储格式**：
```json
{
  "type": "good_answer",
  "question": "用户问的是XXX",
  "answer": "AI 的回答是YYY",
  "scenario": "doc_summary",
  "date": "2026-05-17"
}
```

#### 路径 2：踩反馈结构化（实时，配合 P1 反馈细分类）

```
用户点"踩"
    ↓
弹出原因选项（可多选）：
  - "答非所问"
  - "信息错误"
  - "不完整"
  - "风格不喜欢"
  - "其他（请输入）"
    ↓
结构化存入 feedback.json（已有 reason 字段）
    ↓
为路径 3（自审压缩）提供分类数据
    ↓
积累足够多后，云端可分析"什么类型的题学生总踩"
```

#### 路径 3：本地自审压缩模板（压缩时，中等）

修改压缩 prompt，从"生成摘要"升级为"结构化自审"：

```
你最近回答了以下 N 个问题，压缩前请先完成自审：

对每个问题，回答：
  1. 这类问题我处理得好不好？（1-5）
  2. 如果不好，哪里有问题？
  3. 下次遇到同类问题应该怎么想？

然后生成压缩摘要。

自审结论（选 2-3 条最值得记住的）：
[自动写入 memory，source=自审提炼]
```

**注意**：1.5B 模型自审能力有限，建议 8B 模型才触发自审逻辑；1.5B 降级为普通摘要。

### 7.4 在线批量补课机制

**核心洞察**：在线不是为了"实时辅导"，而是为了**批量补课**。

#### 会话复盘（切换到在线时触发）

```
用户从离线切换到在线
    ↓
系统检测：离 线期间积累的踩反馈 + 未压缩 session
    ↓
弹窗提示："检测到 N 条踩反馈 + M 轮对话，是否启动云端补课？"
    ↓
用户确认
    ↓
云端教师做的事：
  1. 读离线期间积累的踩反馈（含结构化原因）
  2. 读未压缩的 session 历史
  3. 输出：一份"学生模型典型错误模式"清单（按问题类型）
     ↓
  → 生成 memory 条目写入（source=在线补课）
```

**与即时纠正的区别**：
- 即时纠正：用户手动指出具体错误，一对一
- 在线补课：云端自动分析历史行为，批量提炼规律

### 7.5 注入增强：按场景选记忆

当前 memory 静态注入，无差异化。

**改进**：注入时按 task_classifier 结果（reasoning/code/text/agent），从 memory 中选最相关的正向范例优先注入。

简化实现：不做复杂排序，只是正向范例权重提高（注入时多带 1 条）。

### 7.6 三种赋能路径对比

| 路径 | 是否需要云端 | 触发时机 | 工程量 | 效果 |
|------|------------|---------|--------|------|
| 正向范例固化 | ❌ | 实时（点赞时） | 小 | 用户立刻感知 |
| 踩反馈结构化 | ❌ | 实时（点踩时） | 小 | 为后续提供数据 |
| 本地自审压缩 | ❌ | 压缩时 | 中 | 中期积累 |
| 会话复盘补课 | ✅ | 在线切换时 | 中 | 批量高效补课 |

**推荐顺序**：路径 1 → 路径 2（合并反馈细分类 P1） → 路径 4（在线补课） → 路径 3（自审压缩，需 8B 模型）
