## 二、分阶段开发（建议 4 个 Sprint）

### Sprint 1: Skill 框架 + 基础技能（核心，先做）

> **目标**：Skill 导入机制跑通，三个内置技能可用

| # | 任务 | 文件 | 具体内容 | 优先级 |
|---|------|------|----------|--------|
| 1 | Skill 打包规范落地 | `skill_loader.py` | ZIP 导入 -> 解压到 `skills/` -> 读 `skill.json` -> 注册到内存列表 -> 持久化 `skills_registry.json` | P0 |
| 2 | Skill 执行引擎 | `skill_loader.py` | `execute_skill(skill_name, params)` -> 参数校验 -> subprocess 执行 `main.py` -> 超时控制 -> 结果捕获 | P0 |
| 3 | 内置技能: 文件操作 | `skill_fileops.py` | 列出目录、搜索文件、读取文本内容、新建文件。**白名单安全**：只允许 `C:\tmp\_local-ai\files\` 下操作，禁止删除/移动 | P0 |
| 4 | 内置技能: Word 读取 | `doc_reader.py` | 分段读取 .docx：首段(2000字)+尾段(500字)+中间标题摘要。表格提取结构（行列数+表头）。依赖 `python-docx` | P0 |
| 5 | 内置技能: Word 生成 | `doc_writer.py` | 模板驱动生成 .docx：报告模板、摘要模板、信函模板。输出到 `files/` 目录。依赖 `python-docx` | P0 |
| 6 | Skill REST API | `skill_router.py` + `server.py` | 从 server.py 拆出技能路由：`POST /api/skill/import`、`GET /api/skill/list`、`POST /api/skill/execute`、`DELETE /api/skill/{name}` | P0 |
| 7 | Skill Tab 前端 | `index.html` | 新增"技能"Tab：已安装技能列表 + 导入ZIP按钮 + 技能详情弹窗 + 执行参数表单 + 结果展示 | P0 |

**Sprint 1 完成标准**：
- 设置页导入 ZIP -> 技能出现在列表
- 点击执行 -> 填参数 -> 返回结果
- 三个内置技能开箱可用（文件操作、Word读取、Word生成）
- 新依赖安装：`pip install python-docx`

## 四、关键设计决策（已确定）

### 4.1 Skill 框架

```
skills/
├── registry.json           # 技能注册表（自动生成）
├── builtin/                # 内置技能（随版本发布）
│   ├── file-ops/
│   │   ├── skill.json
│   │   └── main.py
│   ├── word-reader/
│   │   ├── skill.json
│   │   └── main.py
│   └── word-writer/
│       ├── skill.json
│       └── main.py
└── custom/                 # 用户导入的技能
    └── my-skill/
        ├── skill.json
        └── main.py
```

### 4.2 文件操作沙箱

```
操作范围：C:\tmp\_local-ai\files\{session_id}\
允许操作：读取、创建、搜索
禁止操作：删除、移动、重命名、执行
路径校验：realpath 必须在沙箱目录内
```

### 4.3 权限模式

| 模式 | 读文件 | 写文件 | 联网搜索 | 安装软件 | 敏感操作 |
|------|--------|--------|----------|----------|----------|
| 问答 | ✅ | ❌ | ❌ | ❌ | ❌ |
| 规划 | ✅ | ❌ | ✅ | ❌ | ❌ |
| 执行 | ✅ | ✅（沙箱内） | ✅ | ❌ | 需确认 |
| 员工 | ✅ | ✅（沙箱内） | ✅ | 需确认 | 需确认 |

### 4.4 Word 分段读取策略

```
首次读取：
  1. 前 2000 字 + 最后 500 字 + 中间段落标题
  2. 表格只提取结构（行列数 + 表头）

追问读取：
  3. 指定页/段的完整内容
  4. 表格完整内容
```

### 4.5 server.py 拆分策略

当前 server.py 已较大，v0.8 开始拆分：
- `skill_router.py` — 技能相关 API（Sprint 1）
- 其他路由暂留 server.py，视体量再拆

## 五、风险与注意事项

1. **python-docx 依赖**：需要确认在 Python 3.14 下可正常安装
2. **subprocess 执行 Skill**：需要严格超时控制（默认 30s），防止恶意/死循环脚本
3. **文件沙箱逃逸**：必须用 `os.path.realpath()` 解析路径后校验，防止 `../` 穿越
4. **NPU 上下文限制**：NPU 模式下 ~1840 token 上限，Skill 执行结果注入上下文时需要截断
5. **离线压缩质量**：1.5B 模型自摘要可能丢细节，8B 应该可以接受
6. **前端 index.html 体量**：当前已经不小，新增 Skill Tab 和权限 UI 后需要关注加载性能

## 六、给下一个 AI Session 的提示

1. **先读 `SESSION_HANDOFF.md`** 了解当前项目全貌
2. **按 Sprint 顺序做**，不要跳着来，Sprint 1 是基础
3. **项目约定**：
   - 临时文件放 `C:\tmp\`
   - 日志 `C:\tmp\_local-ai\server.log`
   - 不用 emoji（Windows GBK 兼容）
   - 版本跟模块走，每个 .py 自己管 `__version__`
   - 魔法数字提取为命名常量
   - 系统提示词在 `prompts.py` 统一维护

4. **每完成一个 Sprint 更新 SESSION_HANDOFF.md**
5. **完成后更新 ROADMAP.md**（v0.7 标注为"质量强化版已完成"，v0.8 标注完成状态）
