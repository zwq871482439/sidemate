# Patch 4 测试手册

> 版本：v0.9 Patch 4 (0.9.4) | 日期：2026-06-11
> 测试环境：Windows 本机，Ollama + Vulkan
> 代码目录：`C:\tmp\_Sidemate_0.9_patch4\server\`

---

## 一、启动方式

```bash
cd C:\tmp\_Sidemate_0.9_patch4\server
python server.py
```

启动后浏览器自动打开 `http://localhost:18601`。

**前置条件**：
- Ollama 已安装且运行中（系统托盘可见）
- 至少有一个本地模型（如 qwen3.5:4b）

## A. 启动 & 基础检查（5 项）

### A1. 正常启动
- **步骤**：运行 `python server.py`
- **预期**：
  - 控制台输出 `[STARTUP]` 相关日志，无报错
  - 浏览器自动打开 `http://localhost:18601`
  - 页面加载完成，看到主界面
- **状态**：☐ PASS / ☐ FAIL

### A2. 版本号展示
- **步骤**：观察浏览器标签页标题 + 设置页标题
- **预期**：
  - 浏览器标签页标题为 `桌伴 v0.9`
  - 进入设置页，标题区域显示版本号（如 `v0.9 Patch 4` 或 `v0.9.4`）
- **状态**：☐ PASS / ☐ FAIL

### A3. 健康检查 API
- **步骤**：浏览器访问 `http://localhost:18601/api/health`
- **预期**：返回 JSON `{"status": "ok"}`
- **状态**：☐ PASS / ☐ FAIL

### A4. 安装状态 API
- **步骤**：浏览器访问 `http://localhost:18601/api/onboard/status`
- **预期**：返回 JSON，包含：
  ```json
  {
    "llm_installed": true/false,
    "cloud_configured": true/false,
    "kb_installed": true/false,
    "recorder_installed": true/false,
    "model_loaded": true/false,
    "completed": true/false
  }
  ```
- **状态**：☐ PASS / ☐ FAIL

### A5. 系统信息 API
- **步骤**：浏览器访问 `http://localhost:18601/api/system/info`
- **预期**：返回 JSON，包含 `python_version`, `app_version` 等字段
- **状态**：☐ PASS / ☐ FAIL

## B. 首次使用引导（6 项）

> **重要**：首次引导只在 `localStorage` 中没有 `sidemate_onboarded` 标记时触发。

### B1. 触发首次引导
- **步骤**：
  1. 打开浏览器开发者工具（F12）→ Application → Local Storage
  2. 删除 `sidemate_onboarded` 键（如果存在）
  3. 刷新页面
- **预期**：
  - 出现全屏半透明遮罩 + 居中引导卡片
  - 根据当前安装状态显示对应的 Route 内容
- **状态**：☐ PASS / ☐ FAIL

### B2. Route 1 — 无 AI 引擎（无本地 LLM 且无云端）
- **触发条件**：未安装 LLM 模型包 + 未配置云端 API
- **步骤**：在未安装 LLM 的环境下首次启动
- **预期**：
  - 显示 "Sidemate 需要一个 AI 引擎才能工作"
  - 有 "安装本地模型" 和 "配置云端 AI" 两个按钮
  - 点击按钮跳转到设置页对应区域
- **状态**：☐ PASS / ☐ FAIL

> 💡 **模拟方法**：如果已安装 LLM，可临时在浏览器控制台设置 `localStorage.removeItem('sidemate_onboarded')` 并观察引导显示逻辑。Route 1 在已安装 LLM 的环境下不会触发，这是正常的。

### B3. Route 2 — 有 AI 引擎但无 KB
- **触发条件**：已安装 LLM（或已配云端）但未装 KB 扩展
- **步骤**：只安装 LLM 不装 KB 的环境下首次启动
- **预期**：
  - 显示 "AI 已就绪！"
  - 介绍 Chat 对话和隐私特性
  - 有 "开始使用" 按钮
  - 如果配了云端，额外显示在线模式说明
- **状态**：☐ PASS / ☐ FAIL

### B4. Route 3 — 全功能（LLM + KB）
- **触发条件**：已安装 LLM + KB 扩展
- **步骤**：全功能环境下首次启动
- **预期**：
  - 显示 "全功能就绪！"
  - 介绍 Chat、文库 Tab、对比模式（如有云端）
  - 隐私说明完整展示
- **状态**：☐ PASS / ☐ FAIL

### B5. 关闭引导后不再触发
- **步骤**：
  1. 在引导卡片中点击 "开始使用" 或关闭按钮
  2. 刷新页面
- **预期**：
  - 引导不再出现
  - `localStorage` 中有 `sidemate_onboarded = "1"`
- **状态**：☐ PASS / ☐ FAIL

### B6. Chat overlay — 模型未预热时
- **步骤**：
  1. 确保模型未预热（重启 Ollama 或等待 keep_alive 过期）
  2. 进入 Chat 页面
- **预期**：
  - 显示锁屏卡片（"模型加载中"或"预热模型"提示）
  - 不显示旧的 welcome 三步引导卡片
  - 模型预热完成后，锁屏自动消失
- **状态**：☐ PASS / ☐ FAIL

## C. Chat 对话（6 项）

> **前置**：模型已预热（设置页点击"预热模型"或自动预热完成）。

### C1. 本地模式 Chat — 基础对话
- **步骤**：
  1. 确保当前模式为 "本地"（顶部模式标签显示 "本地"）
  2. 在输入框输入 "你好，介绍一下你自己"
  3. 按回车发送
- **预期**：
  - 消息气泡出现，AI 逐字流式输出
  - 输出过程中有打字动画效果
  - 输出完成后停止
- **状态**：☐ PASS / ☐ FAIL

### C2. 本地模式 Chat — 多轮对话
- **步骤**：
  1. 发送 "请记住我的名字是小明"
  2. 等待回复完成
  3. 发送 "我叫什么名字？"
- **预期**：AI 回答中提到 "小明"
- **状态**：☐ PASS / ☐ FAIL

### C3. 本地模式 Chat — 停止生成
- **步骤**：
  1. 发送一个长问题（如 "详细介绍一下中国历史"）
  2. 在输出过程中点击停止按钮
- **预期**：
  - 输出立即停止
  - 停止按钮恢复为发送按钮
  - 已输出内容保留在气泡中
- **状态**：☐ PASS / ☐ FAIL

### C4. 新建对话
- **步骤**：
  1. 点击侧边栏 "新建对话" 按钮
- **预期**：
  - Chat 区域清空
  - 侧边栏新增一条对话记录
- **状态**：☐ PASS / ☐ FAIL

### C5. 上下文指示器
- **步骤**：
  1. 连续发送 5-6 条消息
  2. 观察输入框附近的上下文使用率环形指示器
- **预期**：
  - 环形指示器逐渐填满
  - 接近 80% 时变红色并提示建议新建对话
- **状态**：☐ PASS / ☐ FAIL

### C6. 会话管理
- **步骤**：
  1. 新建对话并发几条消息
  2. 回到侧边栏点击之前的对话
  3. 验证历史消息完整加载
- **预期**：
  - 切换对话后历史消息正确显示
  - 可在对话间自由切换
- **状态**：☐ PASS / ☐ FAIL

## D. 模式切换（4 项）

> **前置**：已配置云端 API Key（设置页 → 云端 AI → 填入 API Key）。

### D1. 本地 → 云端 切换
- **步骤**：
  1. 点击顶部模式标签或下拉菜单
  2. 选择 "云端 AI 模型"
- **预期**：
  - 弹出确认框，提示切换到在线模式
  - 确认后，后端先测试连接
  - 连接成功 → 模式标签变为 "在线"
  - 连接失败 → 弹出错误提示，不切换
- **状态**：☐ PASS / ☐ FAIL

### D2. 云端模式 Chat
- **步骤**：
  1. 切换到云端模式后
  2. 发送 "今天的天气怎么样"
- **预期**：
  - AI 正常回复
  - 回复来自云端模型
- **状态**：☐ PASS / ☐ FAIL

### D3. 云端 → 本地 切换
- **步骤**：
  1. 在云端模式下点击模式标签
  2. 切换回 "本地 AI 模型"
- **预期**：
  - 弹确认框 → 确认后切回本地模式
  - 模式标签恢复为 "本地"
  - 新的 Chat 请求走本地管道
- **状态**：☐ PASS / ☐ FAIL

### D4. 未配置云端时尝试切换
- **步骤**：
  1. 清空云端 API Key（设置页 → 云端 AI → 清除 Key）
  2. 回到 Chat 页面尝试切换到云端模式
- **预期**：
  - 弹出提示 "云端 AI 未配置"
  - 引导用户去设置页配置
  - 不切换模式
- **状态**：☐ PASS / ☐ FAIL

## G. 数据目录 & 缓存（4 项）

### G1. data/ 目录结构
- **步骤**：
  1. 打开 `server/data/` 目录
  2. 检查子目录结构
- **预期**：
  ```
  data/
  ├── cache/
  │   ├── docs/
  │   ├── uploads/
  │   └── files/
  ├── chats/
  ├── kb/
  ├── kbsession/
  └── logs/
  ```
  - `docs/`, `tmp_upload/`, `files/` 不再出现在 `data/` 顶层（已迁移到 `cache/` 下）
- **状态**：☐ PASS / ☐ FAIL

### G2. 数据迁移（从 P3 升级场景）
> **注意**：只有从 P3 旧数据升级时才有迁移，全新安装不需要此测试。

- **步骤**：
  1. 如果之前有 P3 的 `data/docs/` 等旧目录
  2. 启动 P4
  3. 检查是否自动迁移
- **预期**：
  - 旧目录内容迁移到 `data/cache/` 对应子目录
  - 控制台输出 `[DATA-MIGRATE]` 日志
- **状态**：☐ PASS / ☐ FAIL / ☐ 跳过（全新安装）

### G3. 缓存清理
- **步骤**：
  1. 在 `data/cache/docs/` 中放入一个修改时间 > 7 天的文件
  2. 重启应用
- **预期**：
  - 启动日志中有 `[CACHE-CLEANUP]` 相关信息
  - 过期文件被清理
- **状态**：☐ PASS / ☐ FAIL / ☐ 跳过

### G4. 录音块清理（如有纪要扩展）
- **步骤**：
  1. 录制一段音频并转写
  2. 转写完成后检查 `data/recordings/{session_id}/chunks/` 目录
- **预期**：
  - `chunks/` 目录已被自动删除
  - 转写结果正常保存
- **状态**：☐ PASS / ☐ FAIL / ☐ 跳过（无纪要扩展）
