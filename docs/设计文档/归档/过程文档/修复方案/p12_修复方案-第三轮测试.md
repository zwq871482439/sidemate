## 🔴 P0 Bug：模型偷 think 导致几乎 100% fallback

### 现象
GPU 模式下 `qwen3-8b-openvino-int4` 几乎每条回复都偷 `<think` 标签：
- `prompt_builder.py` 已传 `extra_context={"enable_thinking": False}` → 不生效（OpenVINO GenAI 的 Qwen3 模板没正确处理此参数）
- 模型输出 `<think\n>` 后输出正文 → `stream_engine` 的 `ThinkProcessor` 等待 `</think` 闭合标签 → 永远等不到（模型只输出了 `<think\n>`，没有闭合）→ `extract_unclosed` 在 30 字符时触发 → 但此时正文可能还没出来 → 最终 `strip_think` 吞掉一切 → fallback

### 根因分析

**问题链路**：
1. `prompt_builder.py` 第 62-72 行：`think_mode="off"` 时传 `extra_context={"enable_thinking": False}` → 但 OpenVINO GenAI 的 `apply_chat_template` 不支持/忽略此参数
2. 模型输出格式：`<think\n>正文内容`（无闭合标签）
3. `think_processor.py` 第 177 行：`extract_unclosed` 要求 `len(full_output) > 30` 才触发，但模型只输出了 `<think\n>` 就直接跟着正文
4. `stream_engine.py` 第 301-315 行：`process_stream_token` 返回 `wait` → 继续等 token → 但 token 累积后 `full_output` 包含 `<think\n>正文...` → `strip_think` 把所有内容都清除了（因为未闭合标签的正则 `r'<think.*$'` 匹配到末尾）

### 修复方案

#### 修复 A：`think_processor.py` — 增强 `extract_unclosed` 的触发条件

**文件**：`C:\tmp\_local_ai_patch12\core\think_processor.py`
**位置**：第 175-184 行

```python
# 当前代码（问题：> 30 才触发，且 strip_think 会吞掉未闭合标签后的正文）
if not has_end:
    if think_mode == "off" and len(full_output) > 30:
        body = self.strip_think(full_output).strip()
        ...

# 修复后：降低阈值到 10，并增加「有正文」的启发式检测
if not has_end:
    if think_mode == "off" and len(full_output) > 10:
        # 先尝试 strip_think
        body = self.strip_think(full_output).strip()
        if body and len(body) >= 3:
            return {"action": "extract_unclosed", ...}
        # strip_think 吞掉了一切 → 手动提取正文
        # 策略：找到 <think 标签后第一个换行符，之后的内容就是正文
        for start_m in THINK_START_MARKERS:
            si = full_output.find(start_m)
            if si >= 0:
                tag_end = full_output.find(">", si)
                if tag_end < 0:
                    tag_end = full_output.find("\n", si)
                if tag_end >= 0:
                    body = full_output[tag_end + 1:].lstrip("\n").strip()
                    if body and len(body) >= 3:
                        log_scan.info("[TP] off-mode manual body extraction: %d chars" % len(body))
                        return {"action": "extract_unclosed", "think_content": "", "body_text": body, "think_len": 0}
```

#### 修复 B：`think_processor.py` — 改进 `strip_think` 的未闭合标签处理

**文件**：`C:\tmp\_local_ai_patch12\core\think_processor.py`（fallback 分支，第 50-53 行）

```python
# 当前代码：未闭合 think 标签吞掉一切
```

#### 修复 D：`stream_engine.py` — 降低 `extract_unclosed` 首次触发延迟

**文件**：`C:\tmp\_local_ai_patch12\core\stream_engine.py`

## 🟡 P1 Bug：回复内容重复

### 现象
第一条消息"你好"的回复"好的，请告诉我你需要什么帮助？"出现了两次，且有多余换行。

### 根因分析
后端在 `stream_engine.py` 中：
1. 流式输出了 `raw` 阶段的 token（第一次）
2. 在后处理阶段（第 560-652 行），又检测到 think 标签未闭合 → `strip_think` 后得到了正文 → 再次 `yield ("text", body)`（第二次）

**关键代码**：`stream_engine.py` 第 456-468 行：
```python
if not think_folded and not _think_processed and full_output:
    _has_think_start = any(...)
    if _has_think_start:
        _body = mm._think_processor.strip_think(full_output).strip()
        if _body:
            yield ("text", _body)  # ← 第二次输出！
```

和 `_think_processed` 没有正确阻止重复输出。

### 修复方案

**文件**：`C:\tmp\_local_ai_patch12\core\stream_engine.py`
**位置**：第 456-468 行

```python
# 修复：只在 _think_processed=False 且 think_folded=False 且没有通过 raw 输出过正文时才 yield
if not think_folded and not _think_processed and full_output:
    _has_think_start = any(...)
    if _has_think_start:
        _body = mm._think_processor.strip_think(full_output).strip()
        if _body:
            # 检查是否已经在流式阶段输出过这部分内容
            # 如果 raw_yielded_len > 0，说明流式阶段已经输出了部分内容
            if raw_yielded_len == 0:
                total_chars += len(_body)
                yield ("text", _body)
            think_folded = True
        else:
            yield ("think_open", len(full_output))
```

## 📊 修复优先级和影响

| 编号 | 级别 | 修复内容 | 涉及文件 | 风险 |
|------|------|---------|---------|------|
| A | P0 | extract_unclosed 手动正文提取 | `think_processor.py` | 低 |
| B | P0 | strip_think 未闭合标签处理 | `think_processor.py` | 中（影响所有 think 剥离） |
| C | P0 | system prompt 禁 think | `prompt_builder.py` | 低 |
| D | P0 | extract_unclosed 不 break | `stream_engine.py` | 中（流式逻辑变更） |
| E | P1 | 回复重复（后处理二次 yield） | `stream_engine.py` | 低 |
| F | P1 | _lastScrollBottom 声明 | `chat.js` | 无 |

## 🛡️ 修复顺序建议

1. **先修 F**（`_lastScrollBottom`）— 零风险
2. **再修 B**（`strip_think` 未闭合标签）— 这是根因，修复后 `strip_think` 不会吞掉正文
3. **然后修 A**（`extract_unclosed` 增强）— 双保险
4. **然后修 E**（回复重复）— 依赖 B 修好后的行为
5. **然后修 D**（不 break）— 流式优化
6. **最后修 C**（system prompt）— 软性防御，模型可能忽略

## ⚠️ 注意事项

- 修复 B 的正则改动会影响所有使用 `strip_think` 的地方（包括 KB 问答），需要回归测试
- 修复 D 改变了流式循环的 break 逻辑，需要确认不会导致无限循环
- 修复 C 是软性防御（模型可能不听），不能作为主要修复手段
