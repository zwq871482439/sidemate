## 🔴 新发现 Bug 汇总

| # | 严重度 | 描述 | 复现条件 |
|---|--------|------|----------|
| B1 | **P0** | GPU 模式下模型频繁偷 think → 所有回复变 fallback | think_mode=off + GPU 设备 |
| B2 | P1 | 回复内容重复（同一段文字出现两次） | 首条消息 "你好" |
| B3 | P2 | 回复前多余换行 | 每条回复开头 |
| B4 | P2 | `_lastScrollBottom` 未声明 → `sendMessage()` via JS 调用报错 | `renderMessages()` 引用未初始化变量 |
| B5 | P2 | fill+Enter 发送不可靠，需要 fill+eval("sendMessage()") 组合 | 浏览器自动化场景 |

### B1 详细分析（模型偷 think）

**现象**：GPU 模式 + think_mode=off，模型几乎每次都输出 `<think\n>` 开头，导致 strip_think() 吞掉正文 → 触发 fallback。

**证据**（curl SSE 输出）：
```
data: {"type": "token", "content": "<think\n"}
data: {"type": "filter", "warnings": ["回复过短且无中文内容"]}
data: {"type": "truncate", "content": "抱歉，我暂时无法回答这个问题，请稍后再试。"}
```

**根因**：`prompt_builder.py` 中 `extra_context={"enable_thinking": False}` 在 OpenVINO GPU 模式下未被模型充分遵守。

**建议修复方向**：
1. stream_engine 中 detect unclosed `<think` tag 时自动续写正文（而非 strip 整段）
2. 或在 GPU 模式下强制在 prompt 末尾加 `\n` 或特殊 token 抑制 think 输出
3. 短期方案：重复生成（retry once）如果检测到空回复
