# 长文本分段处理 — 功能规划

> "让 8B 模型能处理 50K+ 字的长文档，从能用到好用的质的飞跃，为 v1.X 知识库打基础"

\---

## 核心思路

***\*MapReduce + MemAgent 混合架构\****：每段独立提取结构化知识（Map），用滚动记忆跨段传递信息（MemAgent），超出时自动压缩（Collapse），最终汇总输出（Reduce）。

```
50K字长文档
  ↓ chunker.py 智能分段（按章节/段落/句子边界）
12个 ~2500字的片段
  ↓ 逐段 LLM 调用，每段提取：
  │  【提取信息】【推理】【部分回答】【置信度】【待查问题】
  ↓ 滚动记忆 AggregationMemory（≤800字）
  ↓ 记忆超限 → LLM 压缩（Collapse）
  ↓ 全部读完 → 最终聚合（Reduce）
连贯的完整回答
```

\---

## 关键约束（来自现有架构）

| 约束                             | 值              | 影响                            |
| -------------------------------- | --------------- | ------------------------------- |
| 8B 模型 max_history_chars        | 6000            | 每段 + 提示词 + 记忆必须 ≤ 6000 |
| NPU token limit（这个要考虑GPU） | ~1800           | NPU 上可能只能处理更小的段      |
| Skill 执行在子进程               | 30s timeout     | 分段器不能在 skill 里调 LLM     |
| Agent scratchpad                 | max 20 messages | 分段中间结果不进 scratchpad     |
| 无 RAG/向量基础设施              | —               | v1.0 纯靠 LLM 多轮记忆          |

***\*8B 模型单次处理的字数预算\****：

```
System prompt:          ~800 字
滚动记忆:               ~800 字
当前段内容:             ~2500 字
指令 + 用户问题:        ~400 字
输出空间:               ~1500 字（~750 中文字）
───────────────────────────────
合计:                   ~6000 字（刚好）
```

## 新增文件（~1250 行）

### 1. `chunker.py` — 文本分段器（~250 行）

***\*职责\****：将长文本按语义边界切成适合模型上下文的片段

```
@dataclass
class Chunk:
    index: int              # 0-based
    text: str               # 片段内容
    char_start: int         # 原文起止位置
    char_end: int
    section_title: str      # 章节标题（如有）
    overlap_prefix: str     # 上段末尾（~200字重叠）
    overlap_suffix: str     # 下段开头

@dataclass
class ChunkPlan:
    total_chunks: int
    chunks: List[Chunk]
    strategy: str           # "section" | "paragraph" | "fixed"
    overlap_chars: int
```

***\*分段策略\****（自动选择）：

1. 检测到章节标题（`第X章`、`# 标题`、`一、二、`）→ 按***\*章节\****分段
2. 有段落分隔（`\n\n`）→ 按***\*段落\****分段，合并短段、拆分长段
3. 都没有 → ***\*固定长度\****分段，对齐中文句子边界（`。！？；`）

***\*中文优化\****：

- 绝不在句子中间切断
- 支持中文章节标记检测
- 段间 200 字重叠（保持上下文连贯）

### 2. `chunking_orchestrator.py` — 多轮处理编排器（~400 行）

***\*职责\****：编排逐段 LLM 调用，管理滚动记忆，汇总最终结果

```
@dataclass
class ChunkResult:
    chunk_index: int
    extracted_info: str      # 关键事实/数据/观点
    reasoning: str           # 与前段的关联
    partial_answer: str      # 基于已读内容的初步回答
    confidence: float        # 0.0-1.0
    needs_context: List[str] # 需要后续段确认的问题

@dataclass
class AggregationMemory:
    facts: List[str]              # 累积关键事实（≤20 条）
    entities: Dict[str, str]      # 实体 → 描述
    open_questions: List[str]     # 未解答问题
    summary_so_far: str           # 压缩摘要（≤400 字）
    total_chunks_processed: int
    
    def to_prompt_text(self, max_chars=800) -> str:
        """序列化为可注入 prompt 的文本"""

class ChunkingOrchestrator:
    def __init__(self, model_manager, model_name,
                 mode="extract",  # extract|qa|summarize|analyze
                 max_chunk_context_chars=2500,
                 memory_max_chars=800):
        ...
    
    def process(self, chunk_plan, user_question="",
                yield_callback=None, stop_check=None):
        """
        逐段处理主循环：
        1. 每段：构建 prompt → LLM 调用 → 解析结构化输出 → 更新记忆
        2. 记忆超限 → LLM 压缩（Collapse）
        3. 全部读完 → 最终聚合（Reduce）
        4. 每步 yield SSE 进度事件
        """
```

***\*4 种处理模式\****：（关键！！这个地方要引入问答时候的原文检索，这里要坚决杜绝模型幻觉，这种文档问答要严格依照文档内容，要是没有的话就告诉用户原文没有）

| 模式        | 用途         | Prompt 侧重          |
| ----------- | ------------ | -------------------- |
| `extract`   | 通用知识提取 | 提取关键事实和数据   |
| `qa`        | 回答具体问题 | 针对问题找答案       |
| `summarize` | 全文摘要     | 抓主要论点，压缩细节 |
| `analyze`   | 深度分析     | 推理链，跨段关联     |

## 触发机制

| 触发点                        | 检测方式                         | 动作                     |
| ----------------------------- | -------------------------------- | ------------------------ |
| 文件上传 >8K 字               | server.py 检查 file_content 长度 | 强制 agent + long_reader |
| file_ops 读到 >8K 字          | agent.py 检查结果长度            | 自动升级为 long_reader   |
| 用户说"分析/总结/详细" + 文件 | task_classifier 意图检测         | 路由到 agent             |
| 模型主动调用                  | AgentLoop 自然决策               | 直接执行                 |

## 错误处理

- ***\*单段失败\****：跳过，继续下一段，记忆中标注"[第N段处理失败]"
- ***\*>50% 段失败\****：返回已处理部分 + 错误提示
- ***\*记忆溢出\****：自动调用 LLM 压缩（Collapse）
- ***\*总超时\****：超 agent_timeout 时中断，返回部分结果
- ***\*用户中断\****：每段之间检查 `self._stop`，可随时停止
